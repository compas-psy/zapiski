# KompasCloud — бэкенд КОМПАС.ЗАПИСКИ

Node 22 · Fastify 5 · PostgreSQL 16 · TypeScript (ESM). Слушает порт **3100**
(ADR-0003 §2: порт 3000 занят КОМПАС.Дневником, 25 — почтой; ни тот, ни другой
не трогаются).

## Что этот сервис делает и чего не делает

**Zero-knowledge (ТЗ §2.1.5).** Сервер хранит зашифрованные байты и не может их
расшифровать. Ключей у него нет. Из этого следует всё остальное устройство:

* в схеме БД нет ни одной колонки с открытым текстом заметки — содержимое
  лежит в томе, в базе только метаданные (путь, etag, размер, время);
* CRDT-апдейты хранятся как непрозрачный шифротекст: сервер их складывает и
  отдаёт, но не интерпретирует;
* публиковать markdown сервер не умеет — HTML публикации присылает клиент,
  потому что отрендерить шифротекст невозможно;
* поиска, индексации и превью на сервере нет и быть не может.

Проверяется тестом `test/schema.zero-knowledge.test.ts`: он читает
`migrations/*.sql`, интроспектирует живую схему и ищет присланные байты во всех
текстовых колонках базы.

**Данные не блокируются (ТЗ §5.5).** Истечение подписки закрывает запись и
только её. Чтение блобов, версий, CRDT и манифеста доступно всегда. Это
зафиксировано отдельным набором тестов, потому что SCREENS §9 прямо перечисляет
«блокировку доступа к уже созданным заметкам» среди запрещённого.

**Паролей и SMS нет (ТЗ §5.5).** В схеме нет колонок `password*`, `phone*`,
`otp*`, в коде — ни одного пути отправки SMS. И то и другое проверяется тестом.

## Быстрый старт

```bash
cd server
cp .env.example .env          # заполнить DATABASE_URL и AUTH_SECRET
npm install
npm run migrate               # применить миграции
npm run dev                   # http://127.0.0.1:3100
```

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Запуск исходников напрямую (`--experimental-strip-types`), с перезапуском |
| `npm run build` | Компиляция в `dist/` |
| `npm start` | Запуск собранного `dist/index.js` |
| `npm run migrate` | Применение `migrations/*.sql` |
| `npm run typecheck` | `tsc --noEmit` |
| `npm test` | vitest; Postgres поднимается автоматически, см. ниже |

### Тесты

`npm test` ищет базу в таком порядке:

1. `TEST_DATABASE_URL`, если задан;
2. локальные `initdb`/`pg_ctl` — поднимается одноразовый кластер во временном
   каталоге и гасится после прогона;
3. если Postgres недоступен, наборы, которым он нужен, помечаются пропущенными,
   а остальные (санитайзер, JWT, схема по миграциям, тексты реестра, контракт
   протокола) идут как есть.

Эмулятор Postgres намеренно не используется: проверяются `FOR UPDATE`,
частичные индексы и `ON CONFLICT` — то, на чём держатся квота и одноразовость
magic-токена.

## API

Все ответы об ошибке имеют один вид:

```json
{ "error": { "code": "subscription_expired", "message": "Подписка закончилась. Заметки на месте, синхронизация через облако КОМПАС приостановлена" } }
```

`code` машиночитаемый и стабильный; `message` — дословно из реестра
`BEHAVIOR.md` §11 и пригоден к показу как есть.

Аутентификация — `Authorization: Bearer <access-JWT>`, кроме публичных
эндпоинтов (`/health`, `/p/:slug`, фид обновлений, вебхук ЮKassa).

### Аккаунт

| Метод | Путь | Аутентификация | Описание |
| --- | --- | --- | --- |
| POST | `/api/v1/auth/magic-link` | — | Письмо со ссылкой. Тело: `{email, deviceId, platform?}`. Не чаще 1 письма в 60 с на адрес → иначе `429` |
| GET | `/api/v1/auth/magic-link/callback` | — | `?token=…&device_id=…` (или заголовок `X-Device-Id`). Обмен на сессию |
| GET | `/api/v1/auth/yandex` | — | `?device_id=…` → 302 на Яндекс ID |
| GET | `/api/v1/auth/yandex/callback` | — | Обмен кода на сессию |
| POST | `/api/v1/auth/refresh` | — | `{refreshToken}` → новая пара; старый refresh гасится |
| POST | `/api/v1/auth/logout` | — | `{refreshToken}` — отзыв сессии, идемпотентно |
| POST | `/api/v1/auth/logout-all` | ✓ | Отзыв всех сессий пользователя |
| GET | `/api/v1/auth/me` | ✓ | Профиль |
| POST | `/api/v1/auth/analytics-consent` | ✓ | `{optIn}` — ТЗ §6, аналитика opt-in |

Magic-токен: **одноразовый**, TTL **15 минут**, **привязан к устройству
инициации**. Все четыре причины отказа (нет такого, просрочен, использован,
другое устройство) отвечают `410` с текстом реестра «Ссылка больше не
действует. Прислать новую?» и различаются полем `code`.

Ссылка в письме ведёт на `…/api/v1/auth/magic-link/callback?token=…`. Клиент
обязан добавить к обмену свой `device_id` — тот же, с которого запрашивал вход;
без него обмен возвращает `400 device_id_required`. Для веба это означает, что
письмо открывается на своей странице, которая знает `device_id` из localStorage
и уже оттуда дёргает callback.

### Синхронизация (`SyncBackend` из `@zapiski/core`)

| Метод | Путь | Соответствие контракту |
| --- | --- | --- |
| GET | `/api/v1/vault/manifest` | `list()` → `{entries: RemoteEntry[], quota}` |
| GET | `/api/v1/vault/blob/*` | `get(path)` → байты + `ETag` |
| PUT | `/api/v1/vault/blob/*` | `put(path, data, ifMatch?)` |
| DELETE | `/api/v1/vault/blob/*` | `remove(path)` |
| WS | `/api/v1/vault/live` | `subscribe(onChange)` |
| POST | `/api/v1/vault/crdt/:noteId` | Приём CRDT-апдейтов |
| GET | `/api/v1/vault/crdt/:noteId?since=` | Выдача по курсору |

`GET /manifest` принимает `?since=<mtime ms>` и `?includeDeleted=1` (тогда в
ответе появляется поле `removed` со списком удалённых путей — для досинка
удалений).

`PUT /blob/*`:

* тело — `application/octet-stream`, до 64 МБ (`MAX_BLOB_BYTES`);
* `If-Match: <etag>` — оптимистичная блокировка; расхождение → **412**;
* `If-None-Match: *` — «создать, только если пути ещё нет» → **412**, если есть;
* `X-Note-Id: <id>` — включает автоснимок: предыдущий шифротекст уходит в
  историю версий;
* `X-Device-Name`, `X-Version-Merged: 1` — заполняют `source` и `merged`
  созданного снимка;
* ответ: `{path, etag, mtime, size}` + заголовок `ETag`.

`GET /blob/*` понимает `If-None-Match` и отвечает `304`.

`DELETE /blob/*` принимает `If-Match`. Удаление разрешено **и после истечения
подписки**: иначе упёршийся в квоту пользователь оказывается заперт без выхода,
а ТЗ §5.5 запрещает записывать новое, а не убирать своё.

`POST /crdt/:noteId` принимает либо сырые байты, либо
`{"updates": ["<base64>", …]}` — второе экономит запросы, когда клиент досылает
накопленный оффлайн-хвост. Ответ: `{noteId, seq, accepted}`.

**Websocket `/api/v1/vault/live`.** Токен передаётся заголовком или
`?access_token=` (браузерный `WebSocket` не умеет ставить заголовки). Первым
кадром приходит `{"type":"ready","deviceId":…}`, дальше:

```jsonc
{"type":"changed","path":"Проекты/Идея.md.enc","etag":"\"…\"","mtime":1754731200000,"origin":"<deviceId>"}
{"type":"removed","path":"Проекты/Идея.md.enc","origin":"<deviceId>"}
{"type":"crdt","noteId":"note-42","seq":128,"origin":"<deviceId>"}
```

Только имена путей и идентификаторы — никакого содержимого (ТЗ §6). `origin`
позволяет клиенту не реагировать на собственную запись.

### История версий (ТЗ §4.2)

| Метод | Путь | Описание |
| --- | --- | --- |
| GET | `/api/v1/vault/versions/:noteId` | Список `RemoteVersionSnapshot[]` + `retentionDays` |
| GET | `/api/v1/vault/versions/:noteId/:versionId` | Шифротекст версии |
| POST | `/api/v1/vault/versions/:noteId` | Явный снимок (байты в теле) |

Срок хранения проставляется **в момент записи** по действующему тарифу: 30 дней
на пробном периоде, 365 на подписке. Смена тарифа не укорачивает задним числом
то, что уже сохранено.

`RemoteVersionSnapshot` — это `VersionSnapshot` из контракта ядра без поля
`body`: расшифрованный текст существует только на клиенте, сервер отдаёт байты
отдельным эндпоинтом.

### Подписка (ТЗ §5.5)

| Метод | Путь | Аутентификация | Описание |
| --- | --- | --- | --- |
| GET | `/api/v1/billing/status` | ✓ | Тариф, срок, grace, квота, цены |
| POST | `/api/v1/billing/trial` | ✓ | Пробные 14 дней, один раз |
| POST | `/api/v1/billing/cancel` | ✓ | Отмена автопродления в один тап |
| POST | `/api/v1/billing/yookassa/payment` | ✓ | Создание платежа → `confirmationUrl` |
| POST | `/api/v1/billing/yookassa/webhook` | подпись | Уведомления ЮKassa |
| POST | `/api/v1/billing/google-play/verify` | ✓ | Серверная валидация покупки |

Подлинность вебхука проверяется до применения, двумя независимыми способами:
HMAC-SHA256 по **сырому** телу (`YOOKASSA_WEBHOOK_SECRET`, заголовок
`X-Yookassa-Signature`, принимается hex и base64) и/или список сетей
(`YOOKASSA_ALLOWED_CIDRS`). Если не настроен ни один — вебхук отвечает `503` и
ничего не применяет: непроверенное уведомление не должно выдавать подписку.
Повторы идемпотентны через таблицу `billing_events`.

Google Play проверяется через Play Developer API по сервисному аккаунту;
результату проверки на устройстве сервер не доверяет.

Право на запись считается от календаря, а не от последнего известного статуса:

| Состояние | `canWrite` | Хранение версий |
| --- | --- | --- |
| Оплаченный период идёт | да | 365 дней |
| Льготный период | да | 365 дней |
| Пробный период | да | 30 дней |
| Всё истекло | **нет** | как было |

При `canWrite = false` запись отвечает `402` с текстом реестра «Подписка
закончилась. Заметки на месте, синхронизация через облако КОМПАС
приостановлена». Чтение продолжает работать.

### Публикация по ссылке (ТЗ §5.3, P1)

| Метод | Путь | Описание |
| --- | --- | --- |
| POST | `/api/v1/publish` | `{html, title, lead?, noteId?, slug?, publishedAt?}` → `{slug, url}` |
| GET | `/api/v1/publish` | Свои страницы |
| DELETE | `/api/v1/publish/:slug` | Снять публикацию |
| GET | `/p/:slug` | Публичная страница, без аутентификации |

HTML присылает клиент — сервер ключей не имеет. Присланное проходит через белый
список тегов и атрибутов (`src/lib/sanitizeHtml.ts`), а страница отдаётся с
`Content-Security-Policy`, в которой вовсе нет `script-src`: при
`default-src 'none'` скрипт не выполнится, даже если просочится через
санитайзер. Слои независимы намеренно.

Страница собрана по SCREENS §10b `4j`: колонка 620, Source Serif 4, дата моно,
H1 40/600, лид 19 secondary, линия, текст 18/1.75, цитата с левой линией,
подвал «Опубликовано из ЗАПИСОК · только чтение» и вордмарк. Ни шапок, ни
кнопок, ни призывов установить приложение, ни единого обращения к CDN — визит
никому не сообщается.

Сам документ лежит в томе, а не в колонке БД: единственный открытый текст в
системе — тот, который пользователь опубликовал сам, и держать его в базе рядом
с зашифрованными данными незачем.

### Обновления и служебное

| Метод | Путь | Описание |
| --- | --- | --- |
| GET | `/api/v1/updates/:platform/:currentVersion` | Фид для Tauri updater |
| GET | `/health` | Проба: база + том. `200` / `503` |
| GET | `/health/live` | Процесс жив |

Фид отдаёт `{version, notes, pub_date, platforms{target:{signature,url}}}` или
**204 без тела**, если обновления нет — именно так это понимает Tauri.
`:platform` принимается и как `windows`, и как `windows-x86_64`. Для Android в
`platforms` лежит ключ `android-*` со ссылкой на APK.

Источник — JSON по пути `UPDATES_MANIFEST_PATH`:

```json
{
  "version": "1.4.0",
  "notes": "Починили ввод на Gboard",
  "pub_date": "2026-08-09T10:00:00Z",
  "platforms": {
    "windows-x86_64": { "signature": "…", "url": "https://…/zapiski_1.4.0.msi" },
    "android-universal": { "signature": "", "url": "https://…/zapiski-1.4.0.apk" }
  }
}
```

## Схема БД

Миграции — `migrations/*.sql`, применяются `npm run migrate`. Раннер держит
`schema_migrations (version, checksum, applied_at)` и останавливается, если
содержимое уже применённого файла изменилось: правка применённой миграции —
это тихое расхождение схемы между окружениями.

| Таблица | Назначение | Чего в ней нет |
| --- | --- | --- |
| `users` | Аккаунт: почта, `yandex_id`, `analytics_opt_in` | пароля, телефона |
| `devices` | Устройства пользователя | человекочитаемого имени устройства |
| `magic_tokens` | Одноразовые токены входа: `token_hash`, `device_key`, `expires_at`, `used_at` | самого токена — только SHA-256 |
| `sessions` | Сессии: `refresh_token_hash`, срок, отзыв | самого refresh-токена |
| `blobs` | Метаданные блоба: `path`, `etag`, `size`, `mtime`, `storage_key` | **содержимого** |
| `crdt_updates` | `ciphertext bytea` + курсор `seq` | расшифрованного апдейта |
| `versions` | Снимки: `storage_key`, `source`, `merged`, `expires_at` | **содержимого** |
| `subscriptions` | Тариф, периоды, grace, провайдер | реквизитов карты |
| `billing_events` | Идемпотентность вебхуков | данных заметок |
| `published_pages` | `slug`, `storage_key`, `content_hash`, `size` | **HTML** — он в томе |
| `quota_usage` | Счётчики по четырём корзинам + `blob_count` | — |

Единственная бинарная колонка во всей схеме — `crdt_updates.ciphertext`, и это
проверяется тестом.

### Хранилище блобов

Файлы адресуются по содержимому: ключ — SHA-256 шифротекста, каталог —
`blobs/<userId>/<aa>/<bb>/<sha256>`. Отсюда три полезных свойства:

* запись идемпотентна — повтор ничего не портит;
* снимок в историю версий не копирует байты: строка версии ссылается на тот же
  ключ, а файл удаляется, только когда на него не осталось ссылок;
* имена в томе не повторяют имён в vault'е — из листинга каталога нельзя узнать
  ни одного заголовка заметки. Дедупликация только внутри аккаунта: общий на
  всех том выдавал бы, что у двух людей совпал файл.

Запись атомарна: временный файл в том же каталоге → `fsync` → `rename`.

## Приватность (ТЗ §6)

* Путь внутри vault'а — пользовательские данные (в нём заголовок заметки и
  имена папок). В журнал он не попадает: сериализатор заменяет всё после
  `/vault/blob/`, `/vault/crdt/`, `/vault/versions/` и `/p/` коротким хешем.
* Из query вычищаются `token`, `code`, `access_token`, `refresh_token`,
  `email`, `state`; заголовки `authorization`, `cookie` и подпись вебхука
  редактируются pino.
* IP пишется хешем, а не как есть.
* Аналитика opt-in: `users.analytics_opt_in` по умолчанию `false`, публичная
  страница не содержит ни счётчиков, ни внешних ресурсов.

## Тексты вне реестра

Реестр `BEHAVIOR.md` §11 не покрывает несколько серверных ситуаций. Тексты для
них лежат в `PENDING_REGISTRY` (`src/lib/messages.ts`), написаны по правилам
§11 и ждут внесения в реестр:

| Ситуация | Текст |
| --- | --- |
| Квота облака исчерпана | «В облаке закончилось место. Удалите ненужные файлы или расширьте тариф» |
| Файл больше 64 МБ | «Файл слишком большой для облака — предел 64 МБ» |
| Расхождение etag (412) | «Файл изменился на другом устройстве. Обновите его и попробуйте снова» |
| Нужен вход | «Нужно войти в аккаунт КОМПАС» |
| Сессия истекла или отозвана | «Сессия закончилась. Войдите снова» |
| Не нашли по адресу | «Ничего не нашли по этому адресу» |
| Не разобрали запрос | «Не удалось разобрать запрос» |
| Внутренняя неполадка | «Сейчас не получилось. Попробуйте ещё раз» |
| Оплата недоступна | «Оплата временно недоступна. Попробуйте позже» |
| Публикация выключена | «Публикация по ссылке пока недоступна» |

Отдельно: пауза между письмами настроена на 60 с (SCREENS §2), а текст реестра
говорит «Попробуйте через 30 секунд». Текст оставлен дословным, точное время
уезжает в заголовке `Retry-After`.

## Контракт протокола

ADR-0003 требует, чтобы типы протокола жили в одном месте и рассинхрон ломал
сборку. Прямой импорт из `@zapiski/core` сейчас невозможен: пакет принадлежит
другой команде и не собирается как npm-модуль, а сборка сервера не должна
зависеть от чужого незавершённого дерева.

Поэтому типы объявлены в `src/protocol.ts` структурно идентично контракту, а
`test/contract.conformance.test.ts` читает `packages/core/src/contract.ts` и
падает, если наборы полей `RemoteEntry` и `VersionSnapshot` разошлись или если
эндпоинты перестали покрывать `SyncBackend`. Гарантия та же — то же место в CI.
Когда `@zapiski/core` начнёт собираться, файл заменяется на прямой
`import type` и пару присваиваний.

## Рейт-лимиты

| Область | Лимит |
| --- | --- |
| Всё API | 600 запросов / мин на IP |
| `/api/v1/auth/*` | 20 запросов / 5 мин на IP |
| `POST /auth/magic-link` | 1 письмо / 60 с на адрес почты |

Синк — это много мелких запросов, поэтому общий лимит щедрый, а жёсткий стоит
только на входе: перебор что-то даёт именно там.

## Развёртывание

Образ — `Dockerfile` (multi-stage, `node:22-alpine`, непривилегированный
`node`, `tini` как PID 1, `HEALTHCHECK` на `/health`). Том `/data` держит
блобы; база — в своём контейнере без проброса порта на хост (ADR-0003 §4).

Миграции применяются автоматически при старте, отдельным шагом в деплое их
дублировать не нужно.

## Ограничения, о которых стоит знать

* Шина websocket внутрипроцессная. Развёртывание по ADR-0003 — один контейнер
  `zapiski-api`, этого достаточно. Появится второй — в `LiveBus` добавляется
  мост на `LISTEN/NOTIFY` Postgres; интерфейс не меняется.
* Уборка просроченных версий и magic-токенов идёт таймером раз в час внутри
  процесса. При нескольких репликах это станет дублирующейся работой (не
  ошибкой) и попросит вынести в отдельную задачу.
* `POST /api/v1/billing/yookassa/payment` ходит в сеть и потому не покрыт
  тестами — покрыты разбор уведомления, проверка подписи и применение периода.
