# ADR-0002. Индекс и полнотекстовый поиск без SQLite

* Статус: принято
* Дата: 2026-08-09
* Автор: CTO
* Отклонение от: `docs/spec/README.md` §2.2 («Индекс/поиск — SQLite + FTS5; web — SQLite WASM»)

## Контекст

ТЗ требует FTS-поиск <50 мс на 10 000 заметок с операторами `tag:`, `folder:`,
`before:/after:`, `has:` (§5.2) и оговаривает, что индекс — **производная**,
всегда восстановимая из файлов (§2.1.1).

SQLite WASM в браузере тянет ~1 МБ бинаря, требует OPFS-VFS для персистентности
и даёт другой путь исполнения относительно нативного `rusqlite` на desktop —
то самое расхождение платформ, которое запрещает ADR-0001.

Дополнительно: FTS5 не умеет из коробки ни морфологию русского языка, ни
подсветку совпадений в том виде, в каком её требует `SCREENS.md` §6 (до 3
фрагментов на заметку с контекстом ±40 символов).

## Решение

Собственный инвертированный индекс в `@zapiski/core/index`:

* `Map<term, Set<noteId>>` + позиционные списки для фразового поиска `"точная фраза"`.
* Токенизация с раскладкой регистра и нормализацией `ё → е`; стемминга нет
  (осознанно: для заметок точное совпадение предсказуемее «умного» поиска).
* Операторы разбираются в AST до обращения к индексу; `tag:`/`folder:`/`before:`/
  `after:`/`has:` — фильтры по метаданным, не по тексту.
* Персистентность — снапшот в `.zapiski/index.json` (msgpack-подобная упаковка);
  повреждение или отсутствие снапшота приводит к полной перестройке из `.md`,
  что и требует §2.1.1.
* Зашифрованные заметки в индекс не попадают вовсе (§3.3) — отдельная ветка
  выдачи по имени-плейсхолдеру.

Бюджет §5.2 закреплён тестом `packages/core/test/perf.test.ts` на
сгенерированном корпусе 10 000 заметок.

## Последствия

**Плюсы**

* Один и тот же индекс на всех платформах, нулевой вес бинаря, мгновенный старт.
* Полный контроль над ранжированием (§4 `BEHAVIOR.md`: заголовок > тело, свежесть
  при равенстве) и над подсветкой фрагментов.

**Минусы**

* Индекс держится в памяти. При 10 000 заметок это единицы–десятки МБ — приемлемо;
  при 100 000+ понадобится сегментация. Порог зафиксирован как известное
  ограничение, не как сюрприз.
* Нет SQL-запросов «сбоку» для отладки. Компенсируется отладочным дампом индекса.

## Путь назад

`NoteIndex` — интерфейс. Замена на SQLite WASM / `rusqlite` возможна без правок
UI и sync-слоя.
