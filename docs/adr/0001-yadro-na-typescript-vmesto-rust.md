# ADR-0001. Ядро на TypeScript вместо Rust для MVP

* Статус: принято
* Дата: 2026-08-09
* Автор: CTO
* Отклонение от: `docs/spec/README.md` §2.2 (рекомендация «Ядро — Rust, crate `zapiski-core`»)

## Контекст

ТЗ §2.2 рекомендует ядро (домен, синк, крипто, индекс) на Rust с компиляцией
в WASM для веба и нативной линковкой в Tauri. Отклонения разрешены §2.2
явно — «только с обоснованием в ADR».

Ключевое требование, которое перевешивает всё остальное, — принцип §2.1.3:
**«Один редактор на всех платформах. Главный урок рынка: Obsidian провалил
Android из-за расхождения платформ.»** Тот же принцип обязан распространяться
на ядро: если Windows-сборка ходит в ядро через нативный FFI, Android — через
UniFFI/JNI, а веб — через WASM-мост с иной моделью асинхронности и иным
файловым API, мы получаем три разных пути исполнения одного контракта. Это
ровно тот класс расхождений, на котором сгорел Obsidian.

## Решение

Ядро MVP — пакет `@zapiski/core` на TypeScript, **один и тот же байт-в-байт код**
на всех трёх целях (веб-PWA, Tauri desktop, Tauri Android). Платформа
подключается к ядру **только** через узкий порт `VaultStorage` (чтение/запись/
список/атомарный rename) — единственное место, где платформы вообще
различаются:

| Платформа | Реализация `VaultStorage` |
| --- | --- |
| Web (Chromium) | File System Access API |
| Web (прочие) | OPFS |
| Tauri desktop / Android | Плагин `@tauri-apps/plugin-fs` поверх нативной ФС |

Всё остальное — модель заметки, markdown-разбор, индекс + FTS, CRDT, крипто,
sync-бэкенды — исполняется одним кодом везде.

Библиотеки под требования ТЗ:

| Требование ТЗ | Реализация | Примечание |
| --- | --- | --- |
| CRDT (§2.2: «Automerge или **Yrs**») | **Yjs** | Yrs — это Rust-порт Yjs. Берём оригинал; протокол обновлений совместим |
| AES-256-GCM (§3.3) | **WebCrypto** `AES-GCM` 256 бит | Нативная реализация ОС/браузера, не наша крипто-самодеятельность |
| Argon2id KDF (§3.3) | **hash-wasm** (Argon2id, WASM) | Аудируемая реализация, тест-векторы RFC 9106 |
| FTS <50 мс на 10 000 заметок (§5.2) | Собственный инвертированный индекс на TS | Замер в `packages/core` — см. ADR-0002 |

## Последствия

**Плюсы**

* Сквозной функционал web / Windows / Android гарантирован **конструктивно**, а не
  дисциплиной: расхождение невозможно, код физически один.
* Нет тулчейн-барьера: сборка не требует Rust + wasm32 + Android NDK
  одновременно, CI проще и быстрее.
* Отладка одна на все платформы — критично для QA-приоритета №1 (мобильный ввод).

**Минусы и как их держим под контролем**

* Производительность TS ниже Rust. Перф-бюджеты §6 (ввод <16 мс на заметке 1 МБ,
  открытие <150 мс, FTS <50 мс на 10 000) вынесены в автотесты
  (`packages/core/test/perf.test.ts`) — регрессия ломает CI, а не обнаруживается
  на устройстве.
* Крипто в managed-памяти: JS не даёт гарантированного затирания буферов.
  Митигация — ключевой материал живёт в `CryptoKey` (`extractable: false`),
  расшифрованный текст не пишется на диск никогда (§3.3), автозамок по таймеру.
  Ограничение зафиксировано честно и подлежит пересмотру в ADR-0003.

## Путь назад

Порт `VaultStorage` и внутренние интерфейсы ядра (`NoteIndex`, `SyncBackend`,
`CryptoProvider`) описаны так, чтобы допускать поблочную замену на Rust/WASM без
изменения вызывающего кода. Первый кандидат на перенос — индекс + FTS, второй —
крипто. Перенос не требует трогать UI.
