# Платформы

## Приоритеты

| Платформа | Приоритет | Роль |
| --- | --- | --- |
| **Android (телефон)** | P0 | Главная точка захвата мысли. Редактор должен быть безупречен — это то, что провалил Obsidian |
| **Windows (десктоп)** | P0 | Основное место длинного письма |
| **Веб (PWA)** | P0 | Доступ отовсюду + бесплатная точка входа без установки |
| Android (планшет) | P0.5 | Адаптивный layout из той же кодовой базы, двухпанельный режим |
| iOS / iPadOS | P1 | 6–9 месяцев после запуска |
| macOS | P1 | Вместе с iOS |
| Linux | P2 | Дёшево из Windows-сборки, лояльная аудитория |

Требование заказчика: на Android, Windows и в вебе — **идентичный** функционал.

## Как достигается одинаковость

Не дисциплиной, а строением репозитория. Вся логика и весь интерфейс живут в
общих пакетах; платформенные оболочки — тонкие и содержат только точку входа,
реализацию портов и манифест. Экран, добавленный в одну оболочку и не
добавленный в другую, — блокирующий дефект приёмки (пункт D1).

Единственное, чем платформы различаются, — реализации портов
`VaultStorage` и `PlatformCapabilities`. Подробно —
[`../ARCHITECTURE.md`](../ARCHITECTURE.md) §1–2 и
[../dev/modules/core.md](../dev/modules/core.md#порт-vaultstorage--и-зачем-он).

## Таблица возможностей

Сверено с интерфейсом `PlatformCapabilities` в
`packages/core/src/contract.ts`. Колонка «в коде» — фактическое состояние
версии 0.1.0.

| Возможность | Порт | Android | Windows | Веб | В коде |
| --- | --- | --- | --- | --- | --- |
| Хранилище vault'а | `VaultStorage` | Tauri FS | Tauri FS | FSA (Chromium) / OPFS | ⏳ только `MemoryVaultStorage` |
| Выбор папки vault'а | `pickVaultDirectory()` | ✓ | ✓ | ✓ | ⏳ |
| Биометрия | `BiometricProvider` | Android Keystore | Windows Hello | WebAuthn-PRF, если браузер умеет | ⏳ только интерфейс |
| Хэптика | `HapticProvider` | ✓ | — | — | ⏳ только интерфейс |
| Скрытие содержимого в превью задач | `secureFlag(on)` | `FLAG_SECURE` | ограниченно | — | ⏳ только порт |
| Глобальный хоткей быстрой заметки | `GlobalHotkeyProvider` | — | ✓ (по умолч. `Ctrl+Alt+N`) | — | ⏳ только интерфейс |
| Share-target из других приложений | `ShareTargetProvider` | ✓ | — | — | ⏳ только интерфейс |
| Автообновление | `UpdaterProvider` | APK через фид | Tauri updater | не нужно (PWA) | 🟡 фид на сервере есть, клиентов нет |
| Печать в PDF | `PdfRenderer` | печать WebView | печать WebView | печать iframe | ⏳ только порт |
| Виджеты рабочего стола | — | ✓ (1×1, 2×2 ×2) | — | — | ⏳ |
| Quick Settings tile | — | ✓ | — | — | ⏳ |
| Автозапуск в трей, ассоциация `.md` | — | — | ✓ | — | ⏳ |
| Установка как приложение, offline | — | — | — | PWA | ⏳ |

**Правило отображения.** Возможность, которой на платформе нет, равна `null`, и
интерфейс её **скрывает**, а не показывает выключенной. Прямая цитата
`BEHAVIOR.md` §5.1: «Если платформа не поддерживает — тумблер скрыт, не
„выключен и недоступен“». Пункт D3 приёмочного листа.

## Что работает везде одинаково

Всё остальное. Это не пожелание, а следствие того, что код физически один:

* редактор со всеми элементами разметки и live-preview;
* индекс, поиск и все операторы;
* шифрование, включая веб (в отличие от Bear, где в вебе его нет);
* импорт и экспорт во всех форматах;
* синхронизация через локальную папку, WebDAV, Яндекс.Диск и облако КОМПАС;
* три темы и шесть акцентов, все настройки редактора.

## Форм-факторы и раскладки

Базовый макет — телефон 390×844. Брейкпоинты **600 / 900 / 1200**:

| Ширина | Раскладка |
| --- | --- |
| < 600 | Один столбец: список ⟷ заметка. Библиотека — выезжающая панель. Поиск-«пилюля» и FAB внизу |
| 600–900 | Как мобильный; в альбомной ориентации список и редактор рядом |
| 900–1200 | Две панели (список + редактор), библиотека — оверлей по кнопке |
| ≥ 1200 | Три панели: библиотека 224 · список 288 · редактор (колонка текста max 640, центрирована) |

Тип раскладки объявлен в `packages/app/src/contract.ts` (`Layout`), но
**реализации нет** — см. [scope.md](scope.md).

## Нефункциональные цели по платформам

Из ТЗ §6, ни одна пока не измерена на устройстве:

| Показатель | Цель |
| --- | --- |
| Холодный старт Android | < 1.5 с |
| Холодный старт Windows | < 2 с |
| Размер APK | < 30 МБ |
| Размер Windows installer | < 25 МБ |
| Список 10 000 заметок | Плавный скролл, виртуализация |
| Доступность | WCAG 2.1 AA: контраст ≥4.5:1, touch-target ≥44 dp, TalkBack/Narrator, масштаб шрифта ОС до 200%, `prefers-reduced-motion` |

## Риск-зона №1

ТЗ §2.2 прямо называет главный риск стека: качество WebView-редактора на
Android — IME, Gboard / Яндекс.Клавиатура / SwiftKey, автозамена, свайп-ввод,
скролл при появлении клавиатуры, кириллица.

Что уже сделано: перерисовка live-preview откладывается до `compositionend`,
композиция отслеживается двумя независимыми способами, поведение покрыто
тестами ([../dev/modules/editor.md](../dev/modules/editor.md#проблема-ime)).

Что **не сделано и не может быть сделано без устройств**: регрессия на реальных
клавиатурах. Это QA-приоритет №1 и зафиксированное ограничение среды
([`../ACCEPTANCE.md`](../ACCEPTANCE.md)).
