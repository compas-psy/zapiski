# Платформенные оболочки — `apps/web`, `apps/desktop`, `apps/mobile`

Отвечает на главный вопрос заказчика: **одинаковый ли функционал на трёх
платформах**. Коротко — да, и не благодаря дисциплине, а потому что весь
продуктовый код лежит в общих пакетах, а оболочки физически не содержат ни
одного экрана.

Развёрнутый ответ — в трёх таблицах ниже: что реализовано на каждой оболочке,
какие порты равны `null` и **почему именно** (техническая невозможность против
незавершённой работы).

Смежное: [`../../ARCHITECTURE.md`](../../ARCHITECTURE.md) §1–2 (контракт),
[app.md](app.md) (что оболочка монтирует), [core.md](core.md) (объявление
портов).

---

## Правило, из которого всё следует

В `apps/*` разрешены ровно три вещи: точка входа, реализация платформенных
портов и платформенный манифест. Экран, кнопка, строка продуктовой логики —
блокирующий дефект приёмки.

Возможность, которой на платформе нет, равна `null` — и интерфейс её
**скрывает**, а не показывает выключенной (`BEHAVIOR.md` §5.1). Поэтому
заглушек «как бы умеем» в оболочках нет ни одной: биометрия, которая «как бы»
защищает ключ, хуже отсутствующей — человек считает заметки защищёнными.

| Технология | Vite + PWA | Tauri 2 (Windows) | Tauri 2 Mobile (Android) |

| Собирается | ✅ `vite build`, ~1.5 с | ✅ `tauri build` в CI на `windows-latest` | 🟡 `tauri android build` в CI; локально нужны SDK и NDK |

| Проверено на устройстве | — | — | — |
| Что готово | Все порты, service worker, манифест PWA | Все порты + трей, автозапуск, ассоциация `.md`, единственный экземпляр | Все порты + Kotlin-сторона: биометрия, share, виджеты, Quick Settings, печать, обновление |

зафиксировано в [`../../ACCEPTANCE.md`](../../ACCEPTANCE.md). Утверждения ниже
опираются на код, типы и тесты, а не на прогон.

Незакрытые концы Android — в разделе
[«Android: что осталось»](#android-что-осталось).

## Матрица портов

`✓` — реализовано и работает; `null` — порта нет **по природе платформы**,
элемент скрыт; ⏳ — работа не закончена.

| Порт | `web` | `windows` | `android` |
| --- | --- | --- | --- |
| `VaultStorage` | ✓ File System Access API, фолбэк OPFS | ✓ `plugin-fs` + атомарная запись в Rust | ✓ `plugin-fs` + атомарная запись в Rust |
| `pickVaultDirectory()` | ✓ системный диалог (Chromium) / OPFS | ✓ `plugin-dialog` | ✓ вырожден: всегда каталог приложения (см. ниже) |
| `BiometricProvider` | ✓ WebAuthn-PRF, `null` если браузер не умеет | ✓ Windows Hello (`KeyCredentialManager`) | ✓ Keystore + `BiometricPrompt` |
| `HapticProvider` | `null` | `null` | ✓ |
| `GlobalHotkeyProvider` | `null` | ✓ `Ctrl+Alt+N`, настраивается | `null` |
| `ShareTargetProvider` | `null` | `null` | ✓ `ACTION_SEND` (текст, ссылка, изображение) |
| `UpdaterProvider` | `null` (обновляет браузер) | ✓ апдейтер Tauri + подпись | ✓ свой: фид → APK → системный установщик |
| `secureFlag(on)` | no-op | no-op | ✓ настоящий `FLAG_SECURE` |
| `PdfRenderer` | ✓ печать скрытого iframe | ✓ WebView2 `PrintToPdf` | ✓ `PrintDocumentAdapter` |
| `saveFile()` | ✓ «Скачать» | ✓ системный диалог, путь через Rust | ✓ «Загрузки» через MediaStore |
| `PreferencesStore` | ✓ `localStorage` + событие `storage` | ✓ `plugin-store` → `%APPDATA%` | ✓ `plugin-store` |
| `takeInitialIntent` / `onIntent` | ⏳ не объявлены | ⏳ не объявлены | ⏳ не объявлены |
| `publishWidgetSnapshot` | `null` по природе | `null` по природе | ⏳ механизм готов, порт не объявлен |

Три последних поля `AppHost` — необязательные (`?`) и появились в контракте
позже остальных, по итогам сборки Android-оболочки. **Пока их не объявляет ни
одна оболочка и не вызывает `packages/app`**: виджет «Записать», плитка Quick
Settings, чекбоксы в виджете «Закреплённая», открытие `.md` из проводника
Windows и глобальный `Ctrl+Alt+N` доставляют своё событие до границы контракта
и там останавливаются. Исключение — быстрая заметка на Windows: `App.tsx`
обходит дыру, вызывая `createNote()` прямо из `globalHotkey`.

### Почему `null` — это не недоделка

| Порт и платформа | Причина |
| --- | --- |
| **Хэптика на Windows и в вебе** | ТЗ §5.4 закрепляет тактильный отклик за Android. У настольной машины нет ни вибромотора, ни системного API; играть вместо него звук — не «деликатная хэптика», а её пародия |
| **Глобальный хоткей на Android** | Платформа не даёт приложениям ни системных акселераторов, ни фонового слушателя клавиатуры. Эквивалент быстрой заметки — плитка Quick Settings и виджет 1×1 (BEHAVIOR §8) |
| **Глобальный хоткей в вебе** | Страница не может занять сочетание поверх всех окон ОС |
| **Share-target на Windows** | Системный «Поделиться» отдаёт данные только MSIX-пакетам с манифестом `windows.shareTarget`; установщики NSIS/MSI в этот механизм не попадают. ТЗ §5.4 и не требует его на Windows |
| **Share-target в вебе** | В `manifest.webmanifest` `share_target` не объявлен: приём файлов Web Share Target есть только в Chromium на Android, а PWA там — не основной сценарий (там ставится приложение). Технически возможно, продуктово не решено |
| **Апдейтер в вебе** | Обновление ставит браузер, забирая новую оболочку через service worker. Отдельный порт был бы имитацией |
| **`secureFlag` на Windows** | У Windows нет списка задач со снимками экрана — Alt+Tab показывает живую миниатюру DWM, и флага «не показывать содержимое» для неё не существует. Ближайший родственник `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` решает другую задачу: он делает окно невидимым для **любого** захвата, включая демонстрацию экрана и скриншот, который человек делает сам. Молча отбирать это — не то, что просит §5.3, поэтому здесь честный no-op |
| **`secureFlag` в вебе** | Вкладку нельзя скрыть из превью задач. Содержимое защищает автозамок из того же §5.3 |
| **Выбор произвольной папки на Android** | Scoped storage: произвольный каталог общей памяти приложению недоступен, а SAF отдаёт дерево `content://`, поверх которого нет ни атомарного `rename`, ни обычного пути для Rust. Поэтому диалога нет — есть каталог приложения во внешней памяти с настоящими `.md`. Сценарий «мой vault в другой папке» закрывается синком, а не выбором папки |

### Владелец в портах хранилища, и почему вопрос не имеет права писать

Всё, что отвечает на вопрос «где лежат заметки», принимает владельца:
`pickVaultDirectory(owner)`, `restoreVault(owner)` и все три метода
`VaultFolderPicker`. Хранилище принадлежит учётке (модель Obsidian: смена
личности — смена папки), и порт, который про владельца не знает, неизбежно
отвечает про чужое место.

Второе правило жёстче и стоило дня разбирательств. **Вопрос не меняет мира.**
`current()` — это вопрос; экран настроек задаёт его на каждую перерисовку, а
`boot()` — на старте. Пока внутри него стояла заявка на папку («первый
спросивший занимает старое место»), судьбу папки решал порядок вызовов: вопрос
задавался до восстановления сессии, владельцем в тот момент был `local`, и
папка вошедшего человека доставалась ему. Учётка получала пустую подпапку,
синхронизация исправно уносила в облако пустоту.

Поэтому заявку делает тот, кто **открывает** хранилище (`adoptSafTree` в
`apps/mobile/src/platform/capabilities.ts`), а не тот, кто про него спрашивает.
Сторожа: `apps/mobile/test/vault-owner-folder.test.ts` и
`packages/app/test/vault-owner.test.ts`.

Третье — про сторожей, которые врут о причине. Записать настройку и открыть
папку — разные события с разной ценой. `prefs.set` бросает; если это
исключение долетит до онбординга, тот покажет «Папка недоступна» и уведёт
человека в хранилище в памяти, хотя папка на месте. Отсюда правило: неудача
записи настройки не имеет права выглядеть как отказ файловой системы, а
`openVault` бросает ровно в одном случае — хранилище не открылось.

### «Папка недоступна» имеет ровно один источник

Правило записано после четырёх кругов подряд, каждый из которых стоил
заказчику вечера: он выбирал системным окном свою папку и получал «Папка
недоступна» о папке, которая лежала на месте.

Ломалось каждый раз РАЗНОЕ — доигрывание прерванного переименования, чтение
журнала корзины, снимок индекса, очередь неотправленного, подъём облака,
запись настройки. Общим было одно: все они бросали исключение из
`AppController.openVault`, а вызывающий — онбординг, настройки, смена места —
умеет ловить только исключение и потому объявлял человеку, что пропала папка.
Одно сообщение на дюжину разных бед: по нему нельзя ни понять причину, ни
починить.

Теперь:

- **`AppController.openVault` не бросает никогда.** Он возвращает исход:
  `ok` либо `unreadable`. Второе означает ровно одно — прочитать хранилище не
  удалось.
- **Всё, что идёт после открытия, не может отменить открытие.** Служебные
  файлы (`.zapiski/`) читаются в защите: их отказ значит «служебного файла
  нет», а не «папки нет». Индекс перестроится обходом, корзина начнётся
  пустой.
- **Ремонтные операции — не пропускные.** `recoverRename` идёт после проверки
  читаемости и в защите от исключения.
- **Молчаливый выход запрещён так же, как ложное сообщение.** Кнопка «Облако
  Записок» начиналась с `if (!vault) return` — нажималась и не делала ничего.
  Нет хранилища — скажи об этом.

Сторожа: `packages/app/test/onboarding.folder.test.tsx` («поломка ПОСЛЕ
открытия не превращается в „папка недоступна“») и
`packages/core/test/vault-unreadable.test.ts` («ремонтная операция не отменяет
открытие»). Оба проверены фальсификацией.

## Веб (`apps/web`)

Точка входа `src/main.tsx` — 45 строк: собирает `AppHost`, монтирует `<App/>`,
включает PWA-обвязку. Экранов нет.

* **`VaultStorage`** (`vault-storage.ts`) — одна реализация поверх
  `FileSystemDirectoryHandle` покрывает оба случая: File System Access API там,
  где можно показать системный диалог (обычные `.md` в файловой системе
  пользователя — инвариант «file over app»), и OPFS там, где нельзя (Firefox,
  Safari, iOS). Ручка выбранной папки переживает перезапуск: лежит в IndexedDB,
  при старте `restoreVault()` переспрашивает разрешение без диалога выбора.
* **Биометрия** (`biometrics.ts`) — WebAuthn с расширением PRF. WebAuthn
  секретов не хранит, поэтому секрет заворачивается в AES-GCM выводом PRF, а в
  IndexedDB уезжает только шифртекст: без успешной биометрии он бесполезен.
  Нет PRF или платформенного аутентификатора — провайдер `null`, тумблер скрыт.
* **PDF** (`pdf.ts`) — печать скрытого iframe. Байтов у страницы при этом нет и
  быть не может: файл сохраняет сам браузер. `render` возвращает пустой массив,
  и `exportNoteAs` в этом случае ничего не «скачивает» повторно.
* **Настройки** (`prefs.ts`) — `localStorage` с подпиской на событие `storage`:
  смена темы применяется и в соседней вкладке.
* **Service worker** (`public/sw.js`) — навигация: сеть, при отказе оболочка из
  кэша; `/assets/*`: кэш (имена содержат хеш содержимого); остальное с этого
  источника: сеть с тихой подстраховкой; **`/api/*` не кэшируется никогда** —
  очередь изменений ведёт ядро, и «свежий» ответ из кэша сломал бы синк.
  Обновление воркера применяется только по явной команде `skip-waiting`, чтобы
  не оборвать набор текста.
* **Установка PWA** — кнопки «Установить» в оболочке нет намеренно:
  `beforeinstallprompt` не перехватывается, установку предлагает сам браузер.
  Своя кнопка была бы элементом интерфейса, которого нет на Android и Windows.
* **`theme-color`** выставляется из токена `--bg` наблюдением за `data-theme` —
  цветового литерала в оболочке нет (ARCHITECTURE §3.4).
* **`themeInitScript`** вставляется инлайном первым в `<head>` плагином сборки,
  строкой из публичного API `@zapiski/ui`; копии в оболочке нет.

Сборка: `pnpm --filter "@zapiski/web..." build` → `apps/web/dist` (~1.5 с),
раскладывается в `/var/www/zapiski.cmpas.ru`.

## Windows (`apps/desktop`)

Оболочка Tauri 2. TypeScript-часть — только порты; всё, что требует ОС, живёт
в `src-tauri/src/`.

| Модуль Rust | Что делает |
| --- | --- |
| `vault.rs` | `vault_open` (выдаёт каталог в скоупы `fs` и `asset`), `vault_root`, **`vault_write_atomic`** — tmp → fsync → rename одной командой |
| `hello.rs` | Windows Hello: `KeyCredentialManager`, заворачивание секрета в AES-GCM. В JS не попадает ни ключ, ни подпись |
| `hotkey.rs` | Глобальный хоткей через `plugin-global-shortcut`; JS-прав плагину не выдано — занять произвольное сочетание из вебвью нельзя |
| `tray.rs` | Иконка и меню трея, переключатель автозапуска (по умолчанию выключен) |
| `print.rs` | `ICoreWebView2_7::PrintToPdf` — растеризация печатного HTML в байты |
| `save.rs` | Системный диалог сохранения; путь не проходит через вебвью |
| `platform.rs` | Показ окна по сигналу `shell_ready`, проброс аргументов файловой ассоциации, события `zapiski://` |

Особенности, которые видно пользователю:

* окно объявлено скрытым и показывается по сигналу фронтенда — нет ни белой
  вспышки, ни прыжка окна из центра экрана в своё прошлое положение;
* один экземпляр (`plugin-single-instance`): двойной клик по `.md` не поднимает
  вторую копию на том же vault'е;
* закрытие окна прячет приложение в трей **только если включён автозапуск** —
  человек заводил его как резидентное; без автозапуска закрытие означает выход;
* `fs:allow-write-file` оболочке намеренно не выдан: записать в обход атомарной
  команды нечем;
* ассоциация `.md`/`.markdown` объявлена в `tauri.conf.json`, бандлы — NSIS
  (обновления) и MSI (развёртывание политиками домена).

Автообновление: `plugin-updater`, эндпоинт
`https://zapiski.cmpas.ru/api/v1/updates/windows/{{current_version}}`,
проверка раз в сутки, установка — с согласия пользователя.

> ⚠️ В `tauri.conf.json` в поле `plugins.updater.pubkey` стоит строка-заглушка
> `ЗАМЕНИТЬ-НА-НАСТОЯЩИЙ-ПУБЛИЧНЫЙ-КЛЮЧ`. Это не забытая правка: пара ключей
> генерируется один раз при первом релизе
> (`pnpm --filter @zapiski/desktop tauri signer generate`), приватная половина
> кладётся в секрет `TAURI_SIGNING_PRIVATE_KEY`. Workflow сборки проверяет
> заглушку явным шагом и падает с объяснением — подробности в
> [build-and-release.md](../build-and-release.md#windows-tauri-2).

## Android (`apps/mobile`)

Самая большая оболочка из трёх: часть возможностей Android недостижима из
вебвью, поэтому у неё три слоя — TypeScript-порты, Rust-команды и Kotlin.

| Слой | Файлы | Что там |
| --- | --- | --- |
| TypeScript | `src/platform/*.ts` | Порты `VaultStorage`, биометрия, хэптика, share, updater, виджеты, PDF, `saveFile`, настройки; `ipc.ts` — команды и события |
| Rust | `src-tauri/src/*.rs` | `vault_write_atomic`, `secure_flag`, `haptic_impact`, `share_take`, биометрия, печать, файлы, обновление, виджеты. Весь JNI — в одном модуле `android.rs`; на не-Android целях он возвращает честную ошибку, а не тихую заглушку |
| Kotlin | `android/app/src/main/java/ru/cmpas/zapiski/` | `Biometrics.kt`, `ShareActivity.kt`, `Widgets.kt` + `WidgetData.kt`, `QuickNoteTileService.kt`, `PdfPrint.kt`, `Updates.kt`, `Inbox.kt`, `NativeBridge.kt` |

### Оверлей вместо `gen/android` в git

`src-tauri/gen/android` — **сгенерированный** проект Gradle, он в `.gitignore`:
его создаёт `tauri android init` по своему шаблону, вместе с `gradlew`,
`buildSrc` и бинарным `gradle-wrapper.jar`. Держать это в репозитории значило
бы хранить чужой артефакт и ловить конфликт при каждом обновлении Tauri.

Поэтому в git лежит только своё — `apps/mobile/android/**`, а
`scripts/apply-android-overlay.mjs` копирует его в сгенерированный проект и
**патчит** `AndroidManifest.xml` по маркерам: разрешения, share-target, плитка
Quick Settings, `FileProvider`, провайдеры виджетов. Патч, а не замена: шаблон
Tauri задаёт активность, тему и `usesCleartextTraffic`, и полная замена файла
означала бы молчаливый откат его изменений при обновлении CLI. Скрипт
идемпотентен.

Порядок обязателен и проверяется в CI:

```bash
pnpm --filter @zapiski/mobile build:vite                 # cargo-кодогенерация читает ../dist
pnpm --filter @zapiski/mobile exec tauri android init
pnpm --filter @zapiski/mobile android:overlay
pnpm --filter @zapiski/mobile exec tauri android build --apk
```

Патч манифеста проверяется без Android SDK — на эталонном манифесте:

```bash
pnpm --filter @zapiski/mobile android:overlay:selftest    # 22 проверки + xmllint
```

Что уже сделано целиком:

* **биометрия** — AES-ключ в Keystore с `setUserAuthenticationRequired`,
  `BiometricPrompt` с `CryptoObject`; отмена пользователем — это `null`, а не
  ошибка (BEHAVIOR §5.2). `isAvailable()` даёт `true` только при настроенной
  стойкой биометрии на Android 9+;
* **share-target** — `intent-filter` на `ACTION_SEND` (`text/plain`, `image/*`)
  и `ACTION_SEND_MULTIPLE`. Две дороги доставки: событие для работающего
  приложения и очередь `share_take()` для холодного старта, иначе первый же
  share терялся бы;
* **`FLAG_SECURE`** — настоящий флаг окна: содержимое не попадает ни в превью
  задач, ни в скриншот;
* **обновление** — встроенный апдейтер Tauri на Android не работает, поэтому
  свой: фид `/api/v1/updates/android/{{version}}` → APK во внутренний кэш →
  `FileProvider` + системный установщик. Молча ничего не ставится;
* **печать** — скрытый `WebView` даёт `PrintDocumentAdapter`, система рисует
  страницы в PDF;
* **виджеты и Quick Settings** — провайдеры перерисовываются **по факту
  изменения данных, а не по таймеру** (прямое требование §8); тап по чекбоксу в
  виджете кладёт команду в очередь и сразу перерисовывает виджет.

### Android: что осталось

| Что | Состояние |
| --- | --- |
| **Порты намерений ОС не подключены** | `takeInitialIntent`, `onIntent`, `publishWidgetSnapshot` объявлены в `AppHost` (необязательными), но `apps/mobile/src/host.ts` их не отдаёт, а `packages/app` не вызывает. Пока это так, **виджеты честно показывают пустое состояние**, плитка Quick Settings и виджет 1×1 доставляют `zapiski://quick-note` в пустой обработчик, а тап по строке виджета «Последние» ничего не открывает. Оболочка сделала свою половину; вторая — в `packages/app` |
| **Keystore** | `apps/mobile/keystore/` пуст; без секретов `ANDROID_KEYSTORE_*` workflow собирает **debug-APK**. Он ставится на устройство, но релизом не является и не встанет обновлением поверх релизной сборки |
| **APK ни разу не собран** | Локально нет Android SDK/NDK; в CI сборка описана, но её результата пока нет |

Ответ на вопрос «одинаковый ли функционал» на сегодня звучит так: **по коду —
да** (продуктового кода в `apps/*` нет вообще, и это проверяется тестом
инвариантов), **по проверке — на Android ещё нет**, потому что собранного APK
никто не запускал.

## Как добавить платформенную возможность

1. Убедиться, что это **порт**, а не экран. Если появляется хоть одна кнопка —
   она едет в `packages/app`.
2. Объявить интерфейс в `packages/core/src/contract.ts` (владелец файла — CTO,
   правка согласуется).
3. Добавить поле в `PlatformCapabilities` или в `AppHost`
   (`packages/app/src/contract.ts`) — с типом `X | null`, если платформа может
   не уметь.
4. Реализовать во **всех трёх** оболочках или честно вернуть `null` с
   комментарием, объясняющим причину. Комментарий обязателен: без него следующий
   разработчик примет техническое ограничение за недоделку.
5. В `packages/app` — скрывать элемент при `null`, а не показывать выключенным.
6. Обновить таблицу в этом файле и в [`../../product/platforms.md`](../../product/platforms.md).
