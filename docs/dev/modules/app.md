# `@zapiski/app` — экраны и всё поведение

Единственное место в репозитории, где живёт продуктовая логика интерфейса.
Всё, что видит пользователь, собрано здесь; оболочки из `apps/*` только
подставляют платформенные порты и монтируют один компонент.

Публичный API — `packages/app/src/index.ts`. Пакет отдаётся **исходниками**
(`main: ./src/index.ts`), как и `@zapiski/ui`: его CSS обязан пройти через
сборщик оболочки. Скрипт `build` здесь — `tsc --noEmit`, то есть проверка
типов, а не компиляция.

Зависимости: `@zapiski/core`, `@zapiski/editor`, `@zapiski/ui`; React 19 в
peer-зависимостях.

---

## Что оболочка получает наружу

```ts
import { App, type AppHost } from '@zapiski/app';
import '@zapiski/app/styles.css';

createRoot(root).render(<App host={host} locale="ru" />);
```

Оболочке нужно ровно два имени: `App` и `AppHost`. Всё остальное из
`src/index.ts` экспортируется для тестов приёмки и отладочных сборок —
собирать экран самостоятельно оболочка не должна и не может
([`../../ARCHITECTURE.md`](../../ARCHITECTURE.md) §1).

`locale` передаётся пропом, а не читается контроллером из настроек: язык
оболочка знает раньше (системный язык, `navigator.languages`), и если бы
контроллер перечитывал его при старте, выбранный пользователем язык
сбрасывался бы на каждом запуске.

## `AppHost` — контракт с платформой

`src/contract.ts`. Больше приложению от платформы ничего не нужно; если
оболочке «понадобилось нарисовать своё» — не хватает порта, а не экрана.

| Поле | Тип | Зачем |
| --- | --- | --- |
| `platform` | `PlatformCapabilities` | Биометрия, хэптика, глобальный хоткей, share-target, апдейтер, `secureFlag`, выбор папки. Объявлен в ядре |
| `restoreVault()` | `Promise<VaultStorage \| null>` | Открыть vault прошлого запуска. `null` → онбординг с выбором места хранения (SCREENS §1, шаг 2) |
| `prefs` | `PreferencesStore` | Настройки **вне** vault'а: тема, акцент, язык, выбранный бэкенд, автозамок, аккаунт. С реактивной подпиской — смена темы применяется без перезагрузки |
| `openExternal(url)` | `Promise<void>` | Внешняя ссылка и deep link в КОМПАС.Дневник — системным обработчиком, не внутри вебвью |
| `cloudBaseUrl` | `string` | Базовый адрес KompasCloud. Отличается в дев-режиме |
| `pdf` | `PdfRenderer \| null` | Растеризация печатного HTML. `null` → пункт «PDF» в экспорте **скрыт**, а не выключен |
| `saveFile(name, data, mime)` | `Promise<void>` | Отдать готовый файл пользователю: «Скачать» в вебе, системный диалог в оболочках |
| `takeInitialIntent?()` | `Promise<AppIntent \| null>` | Намерение, с которым ОС запустила приложение. Забирается **один раз** |
| `onIntent?(handler)` | `() => void` | Намерения в уже запущенное приложение |
| `publishWidgetSnapshot?(snapshot)` | `Promise<void>` | Данные для виджетов. Вызывается при изменении данных, не по таймеру |

Поля дописывались в конец файла слиянием объявлений — так контракт рос, не
ломая уже написанные оболочки.

`AppIntent` — четыре случая: `new-note` (виджет 1×1, Quick Settings, глобальный
хоткей), `open-note` (тап по строке виджета), `open-file` (ассоциация `.md` на
Windows), `toggle-todo` (чекбокс отмечен прямо в виджете, приложение при этом
не открывается).

> ⏳ **Три необязательных порта пока никто не реализует и не вызывает.** Они
> добавлены в контракт по итогам сборки Android-оболочки: механизмы платформ
> готовы, но позвать приложение им было нечем. Ни одна оболочка их не
> объявляет, ни один экран не подписан. Пока это так, виджеты показывают пустое
> состояние (честно), а быстрая заметка работает только на Windows — там
> `App.tsx` обходит дыру, вызывая `createNote()` прямо из `globalHotkey`.

> **Расхождение, о котором нужно знать.** Семантика `cloudBaseUrl` в оболочках
> разная: `apps/web` отдаёт `origin + /api/v1`, а `apps/desktop` и `apps/mobile`
> — голый `https://zapiski.cmpas.ru`. `SignInScreen` дописывает к значению
> `/auth/magic-link`, поэтому на вебе путь получается верный, а в Tauri-сборках
> — без префикса `/api/v1`. Чинится в оболочках либо приведением контракта к
> «origin без префикса». Подробности про протокол —
> [core.md](core.md#протокол-облака) и [server.md](server.md).

Остальные типы контракта: `Route`, `SettingsSection`, `ScreenState`,
`DebugOverrides`, `Layout`, `Appearance`, `ThemeChoice`, `AccentChoice`.

## Каркас и раскладки

`layoutFor(width)` — четыре раскладки по брейкпоинтам **600 / 900 / 1200**
(SCREENS «Каркас»), пересчёт на `resize` и `orientationchange`:

| Ширина | `Layout` | Что показано |
| --- | --- | --- |
| < 600 | `mobile` | Один столбец: список ⟷ заметка; библиотека — выезжающий `Drawer` |
| 600–900 | `compact` | То же; **в альбомной ориентации** список и редактор рядом |
| 900–1200 | `dual` | Две панели, библиотека — оверлей по кнопке |
| ≥ 1200 | `triple` | Три панели: библиотека · список · редактор |

Ориентация спрашивается отдельным `matchMedia('(orientation: landscape)')`:
ширины 600–900 хватает на две панели не всегда.

`App.tsx` делит экраны на три группы:

* **соло** — занимают окно целиком на любой раскладке: онбординг, вход, импорт,
  paywall, настройки, история версий, поиск (SCREENS §6 — поиск полноэкранный и
  на десктопе);
* **панели** — список (или архив / корзина) и заметка;
* **оверлеи** — палитра команд, отладочное меню, share-лист, `Drawer`
  библиотеки и кнопка возврата из принудительного состояния матрицы.

Режим фокуса убирает хром целиком и оставляет только редактор.

## Состояние: `AppController`

`src/state/store.ts` — один класс, без внешних библиотек состояния. Подписка
через `subscribe` / `getState`, React получает его через
`AppProvider` + `useApp()` / `useAppState()`.

Контроллер владеет `Vault`, `SyncEngine`, `VersionHistory`,
`WebCryptoProvider` и четырьмя таймерами (автозамок, дебаунс поиска, дебаунс
синка, отложенное переименование файла).

Основные группы методов:

| Группа | Методы |
| --- | --- |
| Жизненный цикл | `boot`, `openVault`, `openMemoryVault`, `refresh`, `dispose` |
| Навигация | `navigate`, `back`, `openNote`, `openFolder`, `openTag`, `openSettings`, `setScope` |
| Оверлеи | `toggleLibrary`, `togglePalette`, `toggleInfo`, `toggleFocusMode`, `toggleRawMode`, `toggleDebug`, `toggleShare` |
| Заметки | `createNote`, `save`, `setPinned`, `archive`, `trashNote`, `restoreFromTrash`, `purgeTrash`, `duplicate`, `move` |
| Поиск | `setQuery`, `rememberQuery`, `sortModeFor`, `setSortMode` |
| Шифрование | `encryptNote`, `unlock`, `unlockWithBiometrics`, `hintFor`, `touchLock`, `lockNote`, `lockAll`, `setAutoLockMinutes`, `removeEncryption` |
| Синк | `attachBackend`, `syncNow`, `setOnline`, `reportError`, `clearError` |
| Версии | `versionsFor`, `restoreVersion` |
| Экспорт | `exportNoteAs`, `exportAll` |
| Отладка | `setDebug`, `screenState` |

Важные детали, которые легко нарушить правкой:

* **Расшифрованная заметка живёт только в памяти** (`unlocked`), вместе с
  моментом автозамка. На диск открытый текст не пишется никогда.
* **Автозамок** — один `setInterval` на всё приложение; по умолчанию 10 минут,
  `null` означает «до выхода из приложения». Значение хранится в `prefs`.
* **Задержки после неудачных попыток пароля** берутся из ядра
  (`unlockDelayMs`), данные при этом не удаляются никогда.
* **Ошибка синка** попадает в `syncError` и показывается строкой; в модалку она
  не превращается и ввод не блокирует (инвариант ARCHITECTURE §3.9).
* **Тексты ошибок** приходят из каталога ядра — реестр `BEHAVIOR.md` §11
  существует в одном экземпляре и здесь не копируется.

### Матрица состояний

`MATRIX` — таблица §12 `BEHAVIOR.md`, записанная дословно: девять экранов ×
пять нештатных состояний, `true` — ячейка заполнена в спецификации, `false` —
прочерк. `screenState(screen, isEmpty)` возвращает эффективное состояние:
принудительное из отладочного меню, иначе `loading` → `error` → `offline` →
`empty` → `normal`.

`DebugMenu` не описывает матрицу словами, а **рисует её из `MATRIX`**: прочерк
в ТЗ = выключенная кнопка. Плюс подмена бэкенда синка (`forceSyncBackend`).
Пока состояние принудительное, поверх интерфейса висит кнопка возврата.

Тест `test/matrix.test.ts` разбирает таблицу §12 прямо из
`docs/spec/BEHAVIOR.md` и сравнивает с `MATRIX`: расхождение ломает CI, а не
приёмку.

## Палитра команд

`CommandPalette` строится **из того же массива, из которого собран keymap
редактора** (`editorCommands` пакета `@zapiski/editor`). Копии списка нет:
новая команда редактора появляется в палитре сама, с правильным хоткеем.

Хоткеи оболочки живут в `SHELL_HOTKEYS` (`Ctrl+N`, `Ctrl+Shift+N`, `Ctrl+K`,
`Ctrl+Shift+S`, `Ctrl+\`, `Ctrl+,`, `Ctrl+Shift+E`, `Ctrl+Shift+P`,
`Ctrl+Alt+N`) и обрабатываются в `App.tsx`. Событие с `defaultPrevented`
игнорируется — значит, его уже обработал редактор.

До 8 результатов, три последние команды сверху при пустом запросе, префиксы
`/`, `#`, `>`.

`test/palette.test.ts` проверяет строение: у каждой команды редактора есть
подпись и хоткей, а карта хоткеев оболочки покрывает всё, что §7 отдала
оболочке (приёмочный критерий №8).

## Чего в пакете нет

| Что | Почему |
| --- | --- |
| Подключение `KompasCloudBackend` | Кнопка «Облако КОМПАС» в настройках синка ведёт на paywall. Клиент в ядре написан, но пути протокола расходятся с сервером — [core.md](core.md#протокол-облака) |
| Завершение входа: приём токена magic-ссылки и Яндекс ID | Письмо отправляется, редирект открывается, но обработки возврата в оболочках нет |
| `YandexDiskBackend` в интерфейсе | Класс в ядре есть; кнопка «Подключить» отправляет на экран входа, потому что нужен OAuth-токен |
| Обработка `AppIntent` и публикация `WidgetSnapshot` | ⏳ порты объявлены, подписки и вызова нет. Из-за этого виджеты и плитка Quick Settings на Android доводят событие до границы контракта и останавливаются |
| Экраны «Голос → Markdown» (`3a`–`3e`) | ⏳ P1, не начаты. Компоненты-кирпичи (`MiniPlayer`, `Waveform`, `TimecodeRow`) лежат в `@zapiski/ui` |
| Drag-перестановка элементов списка мышью | ⏳ есть `Alt+↑/↓` в редакторе |

## Правила правки

1. Экран нельзя добавить в оболочку — только сюда. Экран, появившийся в
   `apps/web` и не появившийся в `apps/mobile`, — блокирующий дефект приёмки.
2. Не хватает возможности платформы — добавляется **порт** в `AppHost`, а не
   ветвление `if (platform === 'android')`.
3. Возможность, которой на платформе нет, равна `null`, и элемент
   **скрывается**, а не показывается выключенным (`BEHAVIOR.md` §5.1).
4. Ни одной строки интерфейса внутри компонента — только каталоги i18n.
5. Ни одного hex — только токены `@zapiski/ui` (`pnpm lint:tokens`).
6. Новое поведение — новая строка в `MATRIX`, если оно вводит состояние экрана.

Смежное: [platforms.md](platforms.md) — что из этого доступно на каждой из трёх
оболочек и почему.
