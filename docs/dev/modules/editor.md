# `@zapiski/editor` — редактор

CodeMirror 6 с live-preview: разметка скрыта и проявляется у курсора, layout не
сдвигается никогда. Плюс тонкая React-обёртка.

Публичный API — `packages/editor/src/index.ts`. Пакет **не импортирует
`@zapiski/core`**: всё, что ему нужно от приложения, приходит через объект
`EditorRuntime`.

Два способа использования:

```tsx
// 1. React
import { Editor } from '@zapiski/editor';
<Editor value={text} onSave={save} tags={suggest} wikiExists={exists} />

// 2. Голый CodeMirror
import { zapiskiEditor } from '@zapiski/editor';
new EditorView({
  state: EditorState.create({ doc, extensions: zapiskiEditor({ runtime }) }),
  parent,
});
```

## Ключевое решение: opacity вместо replace

Это главная приёмочная деталь редактора (`BEHAVIOR.md` §2.1 и §13.3,
`DESIGN_TOKENS.md` §3): **разметка у курсора проявляется без единого сдвига
layout**, проверяется покадрово на записи экрана.

Закон файла `live-preview/decorations.ts`:

> Символы разметки (`**`, `#`, `>`, `==`, `[[`, …) **всегда занимают своё место
> в потоке текста**. Меняется только `opacity`: 0 вне активного узла, 1 (цвет
> `--text-disabled`) когда курсор внутри узла или узел попал в выделение.
> Переход 160 мс.

Следствия, которые нельзя нарушать:

* **`Decoration.replace()` не используется ни разу** — он схлопывает символы, и
  строка становится короче ровно в тот момент, когда курсор в неё входит. Это и
  есть тот «прыжок текста», из-за которого live-preview у конкурентов
  раздражает.
* Ни один класс, зависящий от курсора, **не меняет метрику**: ни `font-size`,
  ни `display`, ни `width`, ни `padding`, ни `letter-spacing`. Только `opacity`.
  Даже `.cm-z-highlight` не задаёт `padding` — он сдвинул бы соседний текст.
* Виджеты (чекбокс, картинка) **добавляются**, а не заменяют текст:
  `Decoration.widget`, не `replace`.

Всё, что делает CSS:

```css
.cm-z-mark    { color: var(--text-disabled); opacity: 0; transition: opacity 160ms ease-out; }
.cm-z-mark-on { opacity: 1; }
```

«Активный узел» — узел синтаксического дерева, в диапазон которого курсор
попадает **или к границе которого примыкает** (сравнение `<=`/`>=`). Активность
символа разметки считается по его **родителю**: `#` подсвечивается, когда
курсор где угодно в заголовке, а `**` — когда курсор где угодно внутри жирного
фрагмента.

Производительность: декорации строятся **только по видимым диапазонам**
(`view.visibleRanges`), дерево обходится один раз, результат собирается
`RangeSetBuilder`. Код-блок на тысячу строк не стоит тысячу декораций.
`buildLivePreview(state, ranges)` — чистая функция, не трогает DOM и не требует
`EditorView`, поэтому её же гоняют тесты.

## Проблема IME

Регрессионный тест-кейс №1 (`BEHAVIOR.md` §2.1, приёмка A2): ввод на
Android-клавиатурах без «символов-призраков» — Gboard, Яндекс.Клавиатура,
SwiftKey, автозамена, свайп-ввод, диктовка ОС.

**Правило: перерисовка live-preview откладывается до `compositionend`.**

Почему именно так: CodeMirror сравнивает старый и новый наборы декораций, и
любой изменившийся диапазон внутри композиции заставляет его переписать DOM
composing-узла. Клавиатура теряет контекст — и появляются призрачные символы.

Реализация (`ime/composition.ts` + `live-preview/plugin.ts`):

* Композиция отслеживается **двумя независимыми способами**, чтобы не зависеть
  от прошивки клавиатуры: собственный флаг по `compositionstart`/`compositionend`
  и внутренний детектор CodeMirror `view.compositionStarted`. Достаточно любого.
* Пока `isComposing(view)` истинно, набор декораций только **сдвигается**
  по изменениям документа (`decorations.map(update.changes)`) и **не
  пересчитывается**. Отложенный пересчёт запоминается флагом `pending`.
* `compositionend` сам по себе транзакции не порождает, поэтому в следующем
  такте диспатчится пустая транзакция с `redecorateEffect` — она будит плагин.
* Потеря фокуса посреди композиции (`blur`) тоже разблокирует пересчёт.
* `compositionDeferrals(view)` — счётчик отложенных пересчётов, читается
  тестами (`test/ime.test.ts`).

Автосохранение композицией не блокируется: текст сохраняется как есть,
декорации к этому отношения не имеют.

## `EditorRuntime` — мост с приложением

Редактор не знает ни про хранилище, ни про индекс. Всё внешнее — здесь:

```ts
interface EditorRuntime {
  wikiExists(target: string): boolean;              // иначе ссылка «висячая»
  tags(prefix: string): TagSuggestion[];            // { tag, count }
  notes(query: string): NoteSuggestion[];           // { title, path? }
  haptic(strength: 'light' | 'medium'): void;
  save(text: string): void;                         // автосохранение
  pasteImage(file: File): Promise<string | null>;   // → 'attachments/…'
  openWikiLink(target: string, mode: 'same' | 'aside'): void;
  createNote(title: string): void;                  // тап по висячей ссылке
  openTag(tag: string): void;
  resolveAttachment(src: string): string | null;    // 'attachments/…' → URL
}
```

`noopRuntime` — заглушка: редактор полностью работоспособен и без приложения
вокруг (на ней держатся тесты и витрина). Передаётся фасетом
`editorRuntime.of(...)`; React-обёртка держит колбэки в ref, поэтому ререндер
родителя не роняет ни историю отмены, ни позицию курсора.

## Типографика

Пять пользовательских настроек — **множители над токенами**, задаются CSS-
переменными на корне редактора, поэтому применяются мгновенно, без
переконфигурации состояния:

```ts
typography({ size: 16, lineHeight: 1.65, column: 640, family: 'sans', compact: false })
applyTypography(view, settings);   // на лету
```

`--z-fs`, `--z-lh`, `--z-col`, `--z-face`, `--z-pad-y`, `--z-pad-x`,
`--z-block-gap`. Serif-режим по токенам крупнее на шаг (16 → 17), компактный —
множители 0.906 / 0.909.

Редактор **читает** токены `packages/ui`, но объявляет их имена у себя
(`theme/tokens.ts`) с безопасным fallback: `REQUIRED_SURFACE_TOKENS`,
`REQUIRED_CODE_TOKENS`, `REQUIRED_FONT_TOKENS`. Ни одного hex в пакете нет.

## Автоформатирование при вводе

Принцип: строки, которые markdown и так понимает, **ничего не переписывают** —
их «автоформатирование» это мгновенный live-preview, а не подмена текста.
Меньше магии в буфере — меньше сюрпризов при отмене.

Реально переписывают текст только три случая:

| Ввод | Что делает код |
| --- | --- |
| `[] ` или `- [] ` | `checkboxShortcut` превращает в `- [ ] ` (ловит пробел в `inputHandler`, до попадания в документ) |
| ` ```язык ` + Enter | `completeFencedCode` достраивает закрывающий забор и ставит курсор внутрь |
| `---` + Enter | `completeDivider` вставляет разделитель; при необходимости добавляет пустую строку выше, иначе CommonMark прочитает `---` как setext-заголовок |

Остальное (`- `, `1. `, `# `, `> `) markdown обрабатывает сам.

## Прочее поведение

* **Чекбоксы** (`interactions.ts`). Тап по квадрату — переключение + лёгкая
  хэптика; тап по тексту — обычная постановка курсора. Замена символ-в-символ
  (`[ ]` ↔ `[x]`), длина документа не меняется, отмеченная задача никуда не
  переезжает. Текст выполненной — `--text-secondary` + `line-through`.
* **Теги.** Автодополнение на `#` + минимум 1 символ, до 8 совпадений
  (`COMPLETION_LIMIT`), **сортировка по частоте использования**, вложенные теги
  показываются целиком. Внутри кода подсказки не предлагаются. Тап по тегу —
  `runtime.openTag`.
* **Wiki-ссылки.** `[[` открывает fuzzy-поиск по заголовкам. Висячая ссылка
  (`wikiExists === false`) рендерится акцентом с пунктиром 50% opacity; тап по
  ней — `runtime.createNote`. Ctrl/Cmd+клик — `mode: 'aside'`.
* **Умная вставка** (`smart-paste.ts`, `html-to-markdown.ts`). HTML из буфера
  конвертируется в markdown; картинка уходит в `runtime.pasteImage`; ссылка
  поверх выделения оборачивает его в `[текст](url)`.
* **Режим фокуса.** Активный абзац — 100%, остальные — 28%, переход 300 мс.
  «Абзац» — связная группа непустых строк вокруг курсора. Typewriter-скролл —
  опция, **по умолчанию выключена**. Подсказка «фокус · Esc — выйти» в правом
  верхнем углу.
* **Поиск в заметке.** Штатная панель `@codemirror/search` не подошла:
  англоязычные подписи, нет счётчика, своя вёрстка. Взяты её состояние и
  команды, панель своя — со счётчиком «3 из 12» из каталога строк.
* **Автосохранение.** Debounce `AUTOSAVE_DEBOUNCE_MS = 500` + принудительно на
  blur и при уничтожении представления. `flushAutosave(view)` — немедленно
  (навигация назад, сворачивание приложения). Слова «Сохранить» нет нигде.
* **`prefers-reduced-motion`.** Все переходы (проявление разметки, фокус,
  чекбокс) отключаются в `base-theme.ts`; функциональность полная — приёмочный
  критерий C9.

## Подсветка кода

`syntax/language.ts`: GFM (`markdownLanguage` — с таблицами) плюс расширения
ЗАПИСОК. Курируемый набор из **24 языков** (`codeLanguages`), которые реально
встречаются в заметках; языки грузятся динамически через
`LanguageDescription.load`, поэтому в бандл попадает только то, что встретилось
в тексте. `allCodeLanguages` — полный набор, если нужен.

Палитра подсветки — пастельная, переключается вместе с темой, потому что это
обычные CSS-переменные: `--code-keyword`, `--code-string`, `--code-number`,
`--code-comment`, `--code-function`.

## Как добавить markdown-элемент

На примере уже сделанных (`==подсветка==`, `[[wiki]]`, `#тег`, `[^сноска]`):

1. **Грамматика** — `syntax/markdown-ext.ts`. Опишите `MarkdownConfig`:
   `defineNodes` + `parseInline`/`parseBlock`. Имена узлов **обязательно с
   префиксом `Z`** (`ZHighlight`, `ZHighlightMark`), чтобы никогда не
   столкнуться с именами из `@lezer/markdown`, даже если там появятся свои.
   Парные конструкции делайте делимитерами (`cx.addDelimiter`) — как GFM-
   strikethrough: тогда вложенность в жирный/курсив работает бесплатно.
   Добавьте конфиг в `zapiskiMarkdownExtensions`.
2. **Декорации** — `live-preview/decorations.ts`:
   * символ разметки, который должен фейдиться, — в `FADING_MARKS`;
   * инлайн-стиль, не зависящий от курсора, — в `INLINE_STYLE`;
   * блочный элемент — в `switch (name)` через `this.lines(...)`.
3. **Стиль** — `theme/base-theme.ts`. Только `var(--*)`, ни одного hex.
   **Проверьте, что новый класс не меняет метрику**: если он задаёт
   `font-size`, `padding`, `display` или `letter-spacing` и при этом зависит от
   курсора — вы только что сломали главный приёмочный критерий редактора.
4. **Команда и хоткей** — `commands/formatting.ts` + запись в `editorCommands`.
   Хоткей должен быть в `BEHAVIOR.md` §7; если его там нет, сначала согласуйте
   спецификацию.
5. **Тулбар** — `react/Toolbar.tsx` и иконка в `react/icons.tsx`, если элемент
   нужен на мобильном.
6. **Экспорт** — `packages/core/src/markdown/ast.ts` и рендереры HTML/DOCX:
   иначе элемент будет виден в редакторе, но потеряется при экспорте.
7. **Строки** — только через `i18n.ts`, ни одной подписи в компоненте.
8. **Тест** — `test/live-preview.test.ts`: проверьте, что символы разметки
   получили `cm-z-mark` и что `Decoration.replace` не появился.
