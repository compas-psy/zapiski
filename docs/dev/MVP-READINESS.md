## Fixed

- **EDITOR-001.** Выход из списка на пустом пункте верхнего уровня оставлял
  один `\n` вместо настоящей пустой строки CommonMark — следующий введённый
  абзац становился lazy continuation прежнего пункта и молча возвращался в
  список. Закрывает `bullet/ordered/task list → Enter × 2 → paragraph` из §4.
- **EDITOR-002.** Команда «Обычный текст» (`Ctrl+0`/`Ctrl+Shift+0`) не видела
  Setext-заголовки: маркер (подчёркивание `---`/`===`) живёт на строке НИЖЕ
  содержимого, а команда проверяла только текущую строку и была тихим no-op
  именно там, где её вызывали. Закрывает §7.
- **EDITOR-003.** Вставка (paste) текста, начинающегося с `-`/`*`/`+`/`1.`/`>`/
  `---`/`===`, могла переопределить AST абзаца НАД точкой вставки (например,
  превратить его в Setext-заголовок) — защита существовала только для набора
  одного символа руками, но не для вставки готового блока. Закрывает §9.
- **EDITOR-004.** Правило «нужна ли пустая строка перед новым блоком» жило в
  двух не связанных местах (`commands/formatting.ts`, `input/setext-guard.ts`)
  и было бы неизбежно рассинхронизировано при следующей правке. Сведено в
  `packages/editor/src/syntax/block-boundary.ts` — единый источник для
  `formatting.ts`, `setext-guard.ts`, `lists.ts`, `smart-paste.ts`. Закрывает §8.
- **UX-001.** `FolderPickerDialog` показывал папки плоским списком полных
  путей («Работа», «Работа/Клиенты», «Работа/Клиенты/Иван» одной лентой
  одинаковых кнопок) — заказчик назвал это «максимально уродливым и
  неструктурированным списком папок». Переведён на существующий `Tree` из
  `@zapiski/ui` (тот же компонент, которым уже рисует папки Библиотека) —
  второй `FolderTree` не заведён. Закрывает §16-21.

## Reproduction before

Каждый сценарий воспроизведён диагностикой синтаксического дерева на текущем
HEAD ДО правки (dump документа и Lezer-узлов на каждом шаге), затем —
`git stash`/`git checkout <SHA до фикса>` + falsification (временный откат
правки вернул новые тесты в красное). Полный протокол диагностики — в истории
сессии; здесь только конечные точки.

### bullet list → Enter × 2 → paragraph

Действие: `- Один` → Enter → Enter → набор `Текст`.

- Старый raw markdown: `"- Один\nТекст"` (один `\n`).
- Старый AST: `BulletList[0,6] ListItem[0,6] ListMark[0,1] Paragraph[2,6]` —
  затем при наборе «Текст» диапазон `Paragraph` расширяется до `[2,12]`:
  новый текст стал частью старого пункта списка, а не новым блоком.

### Setext heading recovery

Документ: `Текст\n-----`. Курсор на строке «Текст». Команда «Обычный текст».

- Старое поведение: no-op. `splitLine('Текст')` не находит маркер (он на
  строке `-----`), `applyBlockMarker` не производит ни одного изменения.
  AST остаётся `SetextHeading2[0,11] HeaderMark[6,11]`.

### Paste "---" после абзаца

Документ: `Обычный абзац\n` (курсор на пустой строке 2). Вставка текста `---`.

- Старое поведение: событие `paste` без HTML и без URL падало в финальную
  ветку `smart-paste.ts` — «Обычный текст — return false», событие отдавалось
  браузеру без какой-либо проверки границы.
- Старый результат: `"Обычный абзац\n---"` → парсится как `SetextHeading2`.

## Behavior after

### bullet list → Enter × 2 → paragraph

- Новый raw markdown: `"- Один\n\nТекст"` (настоящая пустая строка).
- Новый AST: `BulletList[0,6] ListItem[0,6] ListMark[0,1] Paragraph[2,6]` как
  сосед `Paragraph[8,13]` — оба топ-уровневые дети `Document`, `Текст` не
  внутри `ListItem`.
- То же для `1. Один` (ordered) и `- [ ] Один` (task) — три отдельных теста в
  `packages/editor/test/input.test.ts`.
- Вложенные пустые пункты не тронуты: штатный `insertNewlineContinueMarkupCommand`
  по-прежнему дедентит их на уровень выше (сохранено намеренно, §4.1).

### Setext heading recovery

- Новый raw markdown: `"Текст\n\n"` — подчёркивание снято целиком (не
  оставлено как thematic break — ровно то поведение, которое требует
  §7 буквальным примером до/после).
- Если ниже есть текст (`Текст\n-----\nСледующий`) — результат
  `"Текст\n\nСледующий"`, абзац `Следующий` не тронут.
- Работает и с `=====` (H1), и с курсором на самой строке подчёркивания.

### Paste "---" после абзаца

- Новый результат: `"Обычный абзац\n\n---"` — абзац остаётся абзацем, `---`
  собственным thematic break/подчёркиванием НЕ становится частью его AST.
- Та же защита сработала для вставленных `- список`, `1. список`, `> цитата`,
  `===`. Вставка внутрь уже существующего списка не получает лишней пустой
  строки (`previousLineIsDangerousNeighbor` пропускает соседей-`ListItem` —
  то же правило, что и у ручного ввода).

- **SEC-020 — REPRODUCIBLE.** `server/package.json:26` всё ещё `"nodemailer":
  "^6.10.0"`, `pnpm-lock.yaml` резолвит `6.10.1`. Свежий `pnpm audit`
  подтверждает 8 действующих advisory для этой версии, включая умеренный

  это единственный факт, который решает вердикт: **RELEASE NO-GO**,
  независимо от состояния P0 editor/FolderPicker работы.

## Known non-blockers

- FolderPicker не прогнан в настоящем браузере отдельным сценарием (только
  модульно, включая один тест с настоящим `AppController`) — компоненты
  (`Tree`, `Modal`) уже браузерно верифицированы в других местах продукта.
- Windows/Android smoke для editor-фиксов не выполнен физически — нет
  тулчейнов/устройств в этой среде; логика платформонезависима.
- P1-аудит Markdown-ловушек §15 (blockquote/fenced-code/inline/links/tables/
  paste-матрица §15.8/IME §15.9) не пройден полным перебором в этой задаче —
  P0-сценарии (список, Setext, paste) покрыты точно по требованию задания;
  расширение до P1-объёма таблицы §15 в объём этой сессии не вошло.
- `docs/dev/testing.md` содержит устаревшие числа тестов («0.1.0», 695 тестов
  всего) — фактически на `4873d8f` их 2317. Не тронуто в этой задаче: не
  входит в объём P0 editor/FolderPicker работы, но стоит обновить отдельной
  правкой документации.

## Owner decisions required

- **SEC-001 (блокирует релиз).** Единственное решение, которое реально
  снимает NO-GO: либо (а) реализовать клиентское шифрование слоя
  `SyncEngine ↔ kompas`-бэкенда до того, как незашифрованные заметки попадают
  в облако (архитектурная задача, прямо вне объёма этого ТЗ), либо
  (б) осознанно отключить/скрыть карточку «Облако Записок» в
  `SettingsScreen.tsx` для этого релиза — и тогда одновременно снять
  обещание «Заметки мы не читаем — технически не можем» из

  `docs/product/monetization.md`/`ARCHITECTURE.md`/`ADR-0003` с тем, что
  реально в проде. Ни то, ни другое не решается кодом этой задачи — решение
  за владельцем продукта, агент его самостоятельно не принимает (§25 ТЗ).
- **SEC-020** (nodemailer): поднять зависимость до версии, где закрыт
  advisory «письмо в чужой домен» — прямо на пути входа по почте; не

- **SEC-007** (zip-бомба): решение об уровне лимита (мегабайты/число файлов)

- **SEC-026** (recent search/paths в prefs): решение — урезать фичу «недавние

- **SEC-027** (валидация путей): чисто инженерная правка, не требует
  продуктового решения — можно закрывать по готовности без дополнительного

## Final verdict

**RELEASE NO-GO.**

Причина — ровно одна, и она не смягчается объёмом остальной проделанной
работы: **SEC-001 воспроизводим на текущем коде, а CMPAS Cloud доступен
обычному пользователю без единого флага или преграды** (Настройки →
Синхронизация → «Облако Записок», вход по Яндекс ID или почте работает на
всех трёх оболочках). Условие §25 «SEC-001 при включённом Cloud → RELEASE
NO-GO» выполнено буквально и, по прямому требованию задания, не подлежит
смягчению агентом.

Это НЕ означает, что P0-работа этой задачи провалена — наоборот, весь её
объём выполнен и доказан фактом:

- Bullet/ordered/task list → Enter × 2 → paragraph, Setext-заголовок
  снимается «Обычным текстом», paste не переопределяет соседний блок —
  исправлено, доказано диагностикой, регрессионной матрицей (48 случаев) и
  настоящим клавиатурным прогоном в Chromium с falsification на каждом шаге.
- FolderPicker переведён на иерархическое дерево тем же компонентом, что и
  Библиотека — 15 новых тестов, 2 существующих обновлены, ни одного нового
  токена дизайна.
- `pnpm -r test`: 2317/2317. `pnpm -r typecheck`: чисто. `pnpm build`: чисто.
  `lint:tokens`: чисто.
- SEC-003 и SEC-029 (закрыты ранее в этой же сессии) не регрессировали.
- SEC-028 обнаружился уже закрытым при пересверке — документация исправлена.

Если бы CMPAS Cloud не была доступна обычному пользователю в этой поставке
(отключена/скрыта продуктовым решением), вердикт был бы **RELEASE READY WITH
KNOWN NON-BLOCKERS** — весь список из раздела «Известные неблокирующие
моменты» ниже квалифицируется именно как non-blocker (ни один не теряет
текст, не раскрывает содержимое заметок, не обходит permissions, не портит
vault и не мешает установке/запуску). Но Cloud доступна, факт проверен
независимо, и по правилу задания это единственное, что решает исход.

**Что нужно, чтобы получить RELEASE READY на следующем прогоне:** решение
владельца по SEC-001 (см. «Owner decisions required» выше) — реализовать
шифрование облачного пути либо отключить Cloud для этого релиза, — после
чего эта пересверка повторяется и, при отсутствии новых находок, вердикт
меняется без необходимости заново доказывать P0-работу редактора и
FolderPicker: она уже доказана и не зависит от решения по Cloud.
