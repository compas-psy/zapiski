# Документы для согласий

**ЧЕРНОВИК. Не публиковать как финальную редакцию без юридической проверки.**

Тексты лежат в `server/legal/` — образ API собирается с контекстом `server/`,
и всё, что вне его, в контейнер не попадает. Здесь — только эта записка.

Это тексты, на которые приложение просит согласие при регистрации.
Написаны они разработчиком, а не юристом, и служат ДВУМ вещам:

1. показать, какие именно сведения и для чего продукт собирает — это
   инженерный факт, и он здесь описан точно;
2. дать юристу заказчика готовую канву вместо чистого листа.

Юридические формулировки, сроки хранения и порядок обращений обязан выверить
юрист — это не сделано и не может быть сделано здесь.

нужно отдельно снимать флаг руками, когда заполните последний email.

## Как заменить текст

1. Правите `server/legal/terms-0.9.md`, `server/legal/privacy-0.9.md`,
   `server/legal/marketing-0.9.md` (или `notes-0.9.md` — Особые условия
   ЗАПИСОК). Правка на месте запрещена для уже выпущенной редакции —
   исправление текста, а не реквизитов, требует новой версии (см. §11 в
   заголовке `server/src/routes/legal.ts`): согласие даётся на конкретную
   редакцию, и после изменения текста прежнее согласие не является согласием
   на новый.
2. Новая версия — новый файл `<slug>-<версия>.md` плюс бамп
   `LEGAL_PACK_VERSION` в `server/src/routes/legal.ts`. Прежний файл не
   трогается: `/legal/<slug>/<старая-версия>` обязан продолжать отдавать
   ровно тот текст, на который человек когда-то согласился.
3. Заполнение реквизитов Оператора (этот раздел) версию не бампает — это не
   правка текста соглашения, а закрытие плейсхолдера, который сам текст и
   предусматривал.
