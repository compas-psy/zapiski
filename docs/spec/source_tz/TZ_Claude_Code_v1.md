# ТЗ для Claude Code — КОМПАС.ЗАПИСКИ

*Техническая спецификация. Версия 1.0. Цель: MVP на Android (mobile/tablet), Windows, Web (PWA); архитектура готова к iOS/macOS/Linux.*

---

## 1. Архитектурные принципы

1. **File over app.** Источник истины — папка с `.md`-файлами и вложениями на устройстве пользователя. Внутренний индекс (SQLite) — производная, всегда восстановим из файлов.
2. **Local-first.** Всё работает полностью оффлайн. Синхронизация — надстройка.
3. **Один редактор на всех платформах.** Главный урок рынка: Obsidian провалил Android из-за расхождения платформ. Редактор — единая кодовая база.
4. **Конфликты не теряют данные — никогда.** Автослияние + версия проигравшей стороны в истории.
5. **Zero-knowledge шифрование.** Сервер не может расшифровать пользовательские данные.

## 2. Технологический стек (рекомендация)

**Монорепо TypeScript + Rust, оболочка Tauri 2:**

| Слой | Технология | Обоснование |
| --- | --- | --- |
| Ядро (домен, синк, крипто, индекс) | **Rust** (crate `zapiski-core`) | Один код для FS, CRDT, шифрования на Win/Android/iOS; надёжность |
| UI | **TypeScript + React** (или Svelte) | Один UI-код на все платформы |
| Редактор | **CodeMirror 6** + кастомные расширения live-preview | Зрелость, производительность, полный контроль над markdown-рендерингом, отличная поддержка IME/кириллицы |
| Desktop (Windows, далее macOS/Linux) | **Tauri 2** | Лёгкий (не Electron), Rust-ядро нативно |
| Android (mobile/tablet), далее iOS | **Tauri 2 Mobile** | Единая кодовая база. **Риск-зона:** до старта — 2-недельный спайк качества WebView-редактора на Android (IME, клавиатуры Gboard/Яндекс, автозамена, скролл при появлении клавиатуры). Fallback-план: React Native с тем же Rust-ядром через UniFFI и редактором в RN WebView/Lexical |
| Web (PWA) | Тот же React + `zapiski-core` в **WASM**; OPFS/IndexedDB для файлов | Максимум переиспользования |
| Индекс/поиск | SQLite + FTS5 (Rust: `rusqlite`); web — SQLite WASM | Мгновенный полнотекст, offline |
| CRDT | **Automerge** (Rust) или Yrs (Yjs-Rust) на уровне текста заметки | Автослияние без конфликтов |
| Облако КОМПАС (backend) | Rust (axum) или Go; PostgreSQL + S3-совместимое хранилище **в РФ** (152-ФЗ) | Blob-синк зашифрованных чанков |

## 3. Модель данных

### 3.1. Файловая структура (vault пользователя)

```
Мои заметки/
  Заметка о встрече.md
  Проекты/
    Идея продукта.md
  attachments/
    2026-08-08_1a2b3c.png
  .zapiski/              # служебное, скрыто
    index.sqlite         # поисковый индекс (восстановим)
    crdt/                # CRDT-логи по заметкам
    versions/            # локальная история версий
    config.json
```

### 3.2. Формат заметки

- Чистый Markdown (CommonMark + GFM: таблицы, чекбоксы, зачёркивание) + расширения: `[[wiki-links]]`, `==highlight==`, сноски, `#вложенные/теги` инлайн.
- YAML frontmatter — опционален, приложение его сохраняет, но не требует (совместимость с Obsidian-vault'ами!). Служебные метаданные (created/updated/pinned/id) — frontmatter при наличии, иначе в индексе.
- Имя файла = заголовок (первая H1/строка), безопасная транслитерация запрещённых символов; переименование обновляет wiki-ссылки.
- **Вложения:** всегда относительные пути `attachments/…`, одинаковая конвенция на всех платформах (фикс главной боли Obsidian). Вставка изображения: копирование в attachments + стандартная markdown-ссылка `![](attachments/…)`.

### 3.3. Шифрование

- Формат `*.md.enc`: контейнер `age`-подобный или собственный: заголовок (magic, версия, salt, nonce) + AES-256-GCM полезная нагрузка (сам md + его вложения-манифест). KDF: Argon2id.
- Ключевая иерархия: master key из пароля → per-note keys. Биометрия разблокирует master key из платформенного keystore (Android Keystore / Windows Hello / WebAuthn-prf на web).
- Зашифрованные заметки: заголовок и тело не попадают в индекс; ищутся только по имени-плейсхолдеру. Расшифровка — в памяти, на диск открытым текстом не пишется.
- Облако КОМПАС: E2E — на сервер уходят только зашифрованные чанки (для платных всё шифруется транспортным слоем vault-ключа независимо от «пользовательского» шифрования заметок).

## 4. Синхронизация

### 4.1. Бэкенды синка (интерфейс `SyncBackend` в ядре)

1. **LocalFolder** — нет синка, просто папка (в т.ч. папка, которую синкает сторонний клиент — Яндекс.Диск-приложение, Syncthing и т.п.).
2. **WebDAV** — универсальный (включая Яндекс.Диск по WebDAV; для Я.Диска — также нативный REST OAuth-коннектор для скорости).
3. **KompasCloud** — собственный протокол: push/pull CRDT-логов и blob-чанков, delta-синк, websocket для мгновенности.

### 4.2. Алгоритм

- Текст заметки — CRDT-документ; `.md` на диске — материализация CRDT (для WebDAV/локали храним и `.md`, и компактный CRDT-лог в `.zapiski/crdt`).
- WebDAV-цикл: ETag/`getlastmodified` → three-way merge через CRDT-лог; если у контрагента нет лога (правили чужим редактором) — line-based three-way merge (diff3); при неразрешимости — обе версии сохраняются, «чужая» уходит в `versions/`, пользователю тихое уведомление «объединили, история тут».
- Правило гибридного режима: **облачная версия — главная**; локальные расхождения вливаются в неё, снапшот локальной — в историю.
- История версий: локально — последние 50 снапшотов/заметку; KompasCloud — 30 дней (free-trial) / 365 (подписка).

### 4.3. Требования к устойчивости

- Прерывание синка на любом байте не портит ни файла (атомарная запись: tmp + rename).
- Часы устройства не влияют на корректность (логические часы CRDT).
- Тест-сьют «злого синка»: параллельная правка одной заметки на 3 устройствах оффлайн → все сходятся к одному состоянию без потерь.

## 5. Функциональные требования MVP

### 5.1. Редактор

- Live-preview: markdown-разметка скрыта, проявляется у курсора (реализация: декорации CodeMirror; эталон поведения — Obsidian Live Preview / Bear).
- Элементы: H1–H6, bold/italic/strike/highlight, списки (маркер/нумерация/чекбоксы, drag-перестановка на desktop), цитаты, код-блоки с подсветкой (~20 языков), таблицы GFM с удобным редактированием (Tab-навигация), изображения инлайн, ссылки, wiki-ссылки с автодополнением, сноски, разделители.
- Тулбар над клавиатурой (mobile), палитра команд Ctrl+K (desktop), полные хоткеи.
- Undo/redo глубиной сессии; автосохранение (debounce 500 мс + on-blur).
- Производительность: заметка 1 МБ — ввод без лагов (<16 мс на кейстрок); открытие заметки <150 мс.
- **Приоритет QA №1:** мобильный ввод — Gboard, Яндекс.Клавиатура, SwiftKey, автозамена, свайп-ввод, кириллица, эмодзи, диктовка ОС. Регрессионные e2e-тесты ввода на реальных устройствах.

### 5.2. Организация и поиск

- Папки (реальные каталоги ФС), вложенные теги, закрепление, архив (`/.archive` или флаг), корзина (`.zapiski/trash`, 30 дней).
- FTS5-поиск: <50 мс на 10 000 заметок; операторы `tag:`, `folder:`, `before:/after:`, `has:image|file|todo`; подсветка совпадений; поиск в заметке Ctrl+F.
- Backlinks: индекс wiki-ссылок и markdown-ссылок между заметками, панель в редакторе.

### 5.3. Импорт/экспорт

- Импорт: папка `.md` (Obsidian-vault как есть, включая attachments), Bear (.bear2bk/textbundle), Notion (zip-экспорт: md+csv → md, csv-таблицы как markdown-таблицы), Evernote (.enex).
- Экспорт: md (zip), PDF, HTML, DOCX — все бесплатно.

### 5.4. Платформенные фичи

- Android: share-target (текст/ссылка/изображение → новая/существующая заметка), виджеты (быстрая заметка, последние), Quick Settings tile.
- Windows: глобальный хоткей быстрой заметки, автозапуск в трей (опция), ассоциация `.md`.
- Web/PWA: установка, offline-режим, File System Access API для локального vault (Chromium), OPFS-vault иначе.

### 5.5. Аккаунт и монетизация

- Локальный режим — без аккаунта вообще.
- Аккаунт КОМПАС (SSO с Дневником): email+код / Telegram login.
- Подписка: платёжный провайдер РФ (ЮKassa) + Google Play Billing; серверная валидация, grace period, восстановление покупок.
- Тарифная логика: free — всё, кроме KompasCloud/публикации; paywall-экраны без блокировки существующих данных при истечении подписки (заметки всегда доступны локально).

## 7. План работ (этапы для Claude Code)

1. **Этап 0 — Спайки (2 нед):** Tauri 2 Android + CodeMirror IME-качество (go/no-go по стеку); прототип CRDT-merge Rust; прототип шифрования.
2. **Этап 1 — Ядро (4–6 нед):** `zapiski-core`: vault, файловый слой, индекс+FTS, модель заметки, CRDT, крипто. CLI-обвязка для тестов. Покрытие ядра тестами >80%.
3. **Этап 2 — Редактор (4–6 нед):** CodeMirror live-preview со всеми элементами §5.1, тулбар, палитра. Витринная заметка из дизайн-ТЗ рендерится пиксель-в-пиксель.
4. **Этап 3 — Приложение (6–8 нед):** экраны по дизайн-системе, Android+Windows+Web сборки, LocalFolder-режим. Внутренняя альфа.
5. **Этап 4 — Синк (4–6 нед):** WebDAV + Яндекс.Диск, «злой синк» тест-сьют, история версий. Закрытая бета.
6. **Этап 5 — Облако и деньги (4–6 нед):** KompasCloud backend, аккаунты, подписка, paywall. Публичный запуск.
7. **Этап 6 — P1:** голос+транскрибация, шаблоны, клиппер, публикация, iOS/macOS.

## 8. Definition of Done (MVP)

- «Злой синк»-сьют зелёный на матрице Android×Windows×Web × (WebDAV, Я.Диск, локально).
- Ввод на Android-клавиатурах без единого бага класса «символы-призраки» (регрессия по списку известных болей Obsidian).
- Импорт реального Obsidian-vault на 1000+ заметок с вложениями — без потерь, ссылки работают.
- Шифрование: независимая проверка (тест-векторы, отсутствие plaintext на диске, memory-safety обзор).
- Перф-бюджеты §6 подтверждены на среднебюджетном Android (класс Redmi/Galaxy A).
