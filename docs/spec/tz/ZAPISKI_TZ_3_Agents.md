# Разделение на агентов — ЗАПИСКИ

**Принцип:** у каждого файла один владелец. Агенты общаются через контракты, а не через чтение чужого кода. Всё, что пересекает границу между агентами, описано заранее и меняется только через архитектора.

---

## 1. Три правила, без которых параллельная работа развалится

1. **Contract-first.** Перед стартом любой пары агентов их общий интерфейс (Rust trait, TS-тип, JSON-схема) написан, закоммичен и заморожен. Изменение контракта = задача архитектору, а не правка «по ходу».
2. **Один владелец на пакет.** Два агента никогда не пишут в один крейт/пакет. Пересечение — сигнал, что граница проведена неверно.
3. **Каждый агент сдаёт тесты, а не «работает у меня».** Приёмка задачи = зелёный тест, который написал сам агент, плюс тест-контракт от потребителя интерфейса.

## 4. Порядок запуска

**Волна 0 — спайки (2 нед).** C0 ставит монорепо и пишет контракты. Параллельно: C4 — спайк IME на Android (главный риск), C2 — спайк CRDT, C3 — спайк Argon2id и WebAuthn, C2 — лимиты Яндекс.Диска. Гейт: решение по мобильному стеку.

**Волна 1 (4–6 нед).** C1 — ядро (критический путь, ни один другой агент без него не сдаст). Параллельно и независимо: C3 — крипто, C8 — каркас бэкенда, C4 — редактор на моках `NoteRepository`.

**Волна 2 (6–8 нед).** C5 — оболочка по макетам D1–D3. C6 — платформенные сборки. C2 — синк поверх готового ядра. C7 — импорт.

**Волна 3 (4–6 нед).** C8 — облако и подписки. C9 — гейты. C0 — интеграция и релиз.

Критический путь: **C0 → C1 → C2/C5 → C9**. C4 идёт параллельно с самого начала на моках — он самый рискованный и должен получить максимум времени.

## 5. Как формулировать задачу агенту

Каждая задача содержит ровно это, иначе не запускается:

```
Роль:        C2, агент синхронизации
Владение:    crates/zapiski-sync/**  (никаких правок вне этого пути)
Контракт:    trait SyncBackend v1.0 — заморожен, см. docs/contracts/sync.md
Вход:        NoteRepository (мок в tests/fixtures)
Задача:      реализовать WebDavBackend
Готово:      сценарии 1–9 из «злого синка» зелёные; ни один не теряет данные
Запрещено:   менять контракт, писать в crates/zapiski-core, хардкодить цвета
```

---

## 6. Мост «дизайн → код»

Единственный артефакт передачи — **`tokens.json`**. Код не читает макеты глазами и не подбирает цвета: он импортирует токены. В CI линтер валит сборку на любом hex-значении в исходниках. Второй артефакт — **витринная заметка** от D1: C4 сдаёт редактор, когда рендеринг совпадает с ней 1:1.

---

## 7. Что нельзя делегировать агентам

Эти решения остаются за основателем и не отдаются ни одному агенту:

- Имя, домен, иконка, тональность текстов.
- Любое расширение скоупа в сторону баз данных, плагинов, коллаборации.
- Цена и структура тарифов.
- **Правило клинического контента** (`0_Master.md` §7). Если агент предлагает демо-данные с клиентом, сессией или диагнозом — это отклоняется без обсуждения.
- Решения по товарным знакам и юрлицу.
