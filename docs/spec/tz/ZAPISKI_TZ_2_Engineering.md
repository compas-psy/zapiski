# ТЗ для Claude Code — ЗАПИСКИ

**Версия 2.0 · финальная.** Цель первого релиза: Android (phone + tablet), Windows, Web (PWA). Архитектура готова к iOS/macOS/Linux без переписывания.

---

## 1. Архитектурные принципы

1. **File over app.** Источник истины — папка с `.md` и вложениями на устройстве. Индекс (SQLite) — производная, восстанавливается из файлов полностью.
2. **Local-first.** Всё работает оффлайн. Синхронизация — надстройка, не условие работы.
3. **Один редактор на всех платформах.** Расхождение платформенных редакторов — причина, по которой конкурент годами не может починить Android.
4. **Конфликты не теряют данные никогда.** Автослияние + проигравшая версия в истории.
5. **Zero-knowledge.** Сервер не может расшифровать пользовательские данные.
6. **Движок отделён от приложения** (решение Р3): ядро и редактор — SDK, приложение ЗАПИСКИ — его первый потребитель, приложение практики — второй.

## 2. Стек

| Слой | Технология | Комментарий |
| --- | --- | --- |
| Ядро | **Rust**, крейты `zapiski-core`, `zapiski-sync`, `zapiski-crypto` | Один код для FS, индекса, CRDT, крипто на всех платформах |
| Биндинги | **UniFFI** (мобайл/натив), **wasm-bindgen** (веб) | Единое API ядра для любого хоста |
| UI | **TypeScript + React** | Один UI-код на все платформы |
| Редактор | **CodeMirror 6** + кастомные расширения live-preview | Зрелость, перф, контроль над IME |
| Desktop | **Tauri 2** (Windows → macOS, Linux) | Легче Electron, Rust-ядро нативно |
| Mobile | **Tauri 2 Mobile** (Android → iOS) | **Условно:** решение принимается по итогам спайка §11.1 |
| Web | React + ядро в WASM, OPFS / File System Access API | Максимум переиспользования |
| Индекс | SQLite + FTS5 (`rusqlite`; в вебе — SQLite WASM) | Мгновенный полнотекст оффлайн |
| CRDT | **Automerge** (Rust) | Автослияние текста без ручного разрешения |
| Бэкенд облака | Rust (axum) + PostgreSQL + S3-совместимое хранилище **в РФ** | Хранит только зашифрованные чанки |

**Fallback-план мобайла** (если спайк провалится): React Native + то же Rust-ядро через UniFFI, редактор в изолированном WebView. Решение принимает агент-архитектор, изменение фиксируется в ADR.

## 3. Модель данных

### 3.1. Структура vault

```
Мои заметки/
  Конспект — Схема-терапия.md
  Проекты/
    Идея продукта.md
  attachments/
    2026-08-11_a1b2c3.png
  .zapiski/
    index.sqlite       # индекс, восстановим из файлов
    crdt/              # CRDT-логи по заметкам
    versions/          # локальная история
    config.json
```

### 3.2. Формат заметки

- CommonMark + GFM (таблицы, чекбоксы, зачёркивание) + расширения: `[[wiki-links]]`, `==highlight==`, сноски, `#вложенные/теги` инлайн.
- YAML frontmatter **опционален**: приложение его сохраняет и не требует. Vault Obsidian открывается как есть.
- Имя файла = заголовок (первая строка / H1). Переименование обновляет все wiki-ссылки атомарно.
- **Вложения — единая конвенция относительных путей на всех платформах** (`attachments/имя`). Это прямой фикс главной боли конкурента: путь, созданный на телефоне, обязан разрешаться на десктопе и в вебе. Покрыть тестом на всех трёх платформах в обе стороны.

### 3.3. Шифрование

- Контейнер `*.md.enc`: magic + версия + salt + nonce + AES-256-GCM payload. KDF **Argon2id** (параметры: 64 МБ, 3 итерации, параллелизм 4 — калибровать под слабый Android).
- Иерархия ключей: пароль → master key → per-note keys. Биометрия открывает master key из платформенного хранилища: Android Keystore · Windows Hello (DPAPI/CNG) · WebAuthn PRF в вебе.
- Зашифрованные заметки не попадают в FTS-индекс. Расшифровка только в памяти; открытый текст на диск не пишется **никогда**, включая временные файлы и swap-подобные механизмы редактора.
- Автозамок по таймауту и при сворачивании приложения (настраивается).

## 4. Синхронизация

### 4.1. Бэкенды (трейт `SyncBackend`)

| Бэкенд | Реализация |
| --- | --- |
| `LocalFolder` | Папка на устройстве, в т.ч. синхронизируемая сторонним клиентом |
| `WebDav` | Универсальный: любой сервер, ETag/`getlastmodified`, батчинг |
| `YandexDisk` | **Нативный REST + OAuth.** WebDAV Яндекс.Диска ограничивает частые операции с мелкими файлами — для него отдельный коннектор с delta-синком; WebDAV остаётся универсальным fallback |
| `ZapiskiCloud` | Свой протокол: CRDT-логи + blob-чанки, delta, WebSocket для мгновенности |

### 4.2. Алгоритм

- Текст заметки — CRDT-документ. `.md` на диске — его материализация. CRDT-лог лежит в `.zapiski/crdt`.
- Цикл: обнаружение изменений → трёхстороннее слияние через CRDT → если у контрагента лога нет (правили сторонним редактором) → line-based diff3 → при неразрешимости обе версии сохраняются, «чужая» уходит в `versions/`, пользователю показывается тихое «объединили, история тут».
- **Гибридный режим:** при подключённом облаке главной считается облачная версия; расхождение локальной вливается в неё, снапшот локальной уходит в историю.
- Атомарная запись (tmp + rename). Прерывание синка на любом байте не портит файл.
- Логические часы CRDT: сбитые системные часы устройства не влияют на корректность.

### 4.3. Приёмка синка («злой синк»)

Матрица: {Android, Windows, Web} × {LocalFolder, WebDAV, Яндекс.Диск, Облако}. Сценарии, все обязаны быть зелёными:
параллельная правка одной заметки на 3 устройствах оффлайн → сходимость без потерь · переименование на одном устройстве при правке на другом · удаление против правки · вставка изображения на телефоне → открытие на десктопе и в вебе · обрыв сети в середине передачи · заполненный диск · часы устройства сдвинуты на ±3 дня · vault на 10 000 заметок / 2 ГБ вложений.

## 5. Редактор

- Live-preview: разметка скрыта, проявляется у курсора (декорации CodeMirror). Переключение в raw по Ctrl+E.
- Элементы: см. `0_Master.md` §4. Таблицы GFM с Tab-навигацией, drag-перестановка списков на десктопе.
- Тулбар над клавиатурой (mobile): H · B · I · список · чекбокс · изображение · «…». **Микрофона в v1 нет** (решение Р4).
- Палитра команд Ctrl+K на десктопе, полный набор хоткеев.
- Автосохранение: debounce 500 мс + on-blur + on-background. Понятия «сохранить» в UI нет.
- Перф: ввод в заметке 1 МБ — <16 мс на нажатие; открытие заметки <150 мс; список 10 000 заметок — виртуализация, плавный скролл.

### 5.1. Мобильный ввод — приоритет QA №1

Матрица обязательна к прогону перед каждым релизом: Gboard · Яндекс.Клавиатура · SwiftKey · Samsung Keyboard · системная AOSP. Проверяется: кириллица, автозамена, свайп-ввод, эмодзи, диктовка ОС, выделение и замена текста, undo после автозамены, скролл при появлении клавиатуры, поворот экрана с открытой клавиатурой, физическая клавиатура на планшете.

**Гейт релиза:** ноль дефектов класса «символы-призраки», «съеденный текст», «курсор прыгает». Это ровно те баги, из-за которых пользователи уходят от конкурента, и наш главный аргумент.

## 6. Поиск и организация

FTS5, <50 мс на 10 000 заметок. Операторы `tag:`, `folder:`, `before:`, `after:`, `has:image|file|todo`. Подсветка совпадений. Поиск внутри заметки. Индекс backlinks (wiki- и markdown-ссылки), инкрементальное обновление при сохранении.

## 7. Импорт и экспорт

**Импорт (P0):** папка `.md` / Obsidian-vault как есть, включая attachments и frontmatter · Bear `.bear2bk` / textbundle · Notion zip (md + csv; csv → markdown-таблицы) · Evernote `.enex` (включая вложения и заметки с HTML → чистый markdown).
Требование: импорт vault на 1 000+ заметок без потерь, все ссылки и изображения разрешаются. Итоговый отчёт со списком непереносимого.

**Экспорт (P0):** md (zip), PDF, HTML, DOCX — бесплатно на всех тарифах.

## 8. Платформенное

**Android:** share-target (текст, ссылка, изображение), виджеты (быстрая заметка, последние, закреплённая — чекбоксы кликабельны прямо в виджете), Quick Settings tile, биометрия, adaptive icon. **Разрешения — минимально возможные:** избыточный запрос доступа ко всем файлам — известная претензия к конкуренту; используем SAF/scoped storage и объясняем каждый запрос в UI.
**Windows:** глобальный хоткей быстрой заметки, трей (опция), ассоциация `.md`, Windows Hello.
**Web/PWA:** установка, оффлайн, File System Access API для локального vault в Chromium, OPFS иначе, WebAuthn PRF для ключей.

## 9. Движок как SDK (решение Р3)

Публичный контракт `zapiski-engine`, который потребляют оба приложения:

```
VaultProvider     — где лежат файлы (путь, бэкенд, политика)
NoteRepository    — CRUD, поиск, backlinks, вложения
EditorHost        — монтирование редактора, тема через tokens.json, режимы
CryptoPolicy      — required | optional | disabled
SyncPolicy        — разрешённые бэкенды
FeatureFlags      — публикация, экспорт, импорт, wiki-ссылки
```

**Профиль `standalone` (приложение ЗАПИСКИ):** CryptoPolicy = optional, все бэкенды синка, все фичи.

**Профиль `host-embedded` (приложение практики):** CryptoPolicy = **required** (шифрование принудительно), SyncPolicy = только серверы РФ, публикация и внешние бэкенды **запрещены**, экспорт — по политике хоста. Это техническая реализация правила из `0_Master.md` §7: клинический контент не может физически оказаться в потребительском vault на WebDAV.

Движок не знает про клиентов, сессии и карточки — хост передаёт только идентификатор контекста, движок хранит его в frontmatter.

## 12. P1 · Голос → Markdown (архитектурный задел закладывается сейчас)

Реализация через 3–6 месяцев, но модель данных фиксируется в P0, чтобы не мигрировать:

- Аудио — обычное вложение в `attachments/`. Карта выравнивания «абзац ↔ таймкод» — **сайдкар** в `.zapiski/`, не в теле заметки. `.md` обязан оставаться чистым и полностью читаемым в стороннем редакторе без сайдкара.
- Расшифровка — **GigaAM** (открытая модель, MIT), оформление — **Qwen** через Ollama. Два места обработки в первом релизе голоса: на устройстве и в облаке (сопряжение с домашним ПК — P2, высокая стоимость поддержки: mDNS в чужих сетях, спящий ПК, изоляция клиентов на роутере).
- Оформление на устройстве доступно только там, где хватает памяти; иначе честно предлагается облако с явным согласием.
- Оригинал расшифровки хранится рядом и возвращается в один тап — модель ничего не «съедает».
- В интерфейсе нет слова «AI», нет искр и градиентов. Кнопка называется «Оформить».
- **Юридический гейт:** перед первой длинной записью — экран согласия; дефолт обработки для профессиональных записей — только на устройстве; в интерфейсе и маркетинге отсутствуют любые подсказки о записи сессий с клиентами.

## 13. Definition of Done первого релиза

- «Злой синк» (§4.3) зелёный на всей матрице.
- Матрица клавиатур (§5.1) — ноль дефектов класса «символы-призраки».
- Импорт реального Obsidian-vault на 1 000+ заметок: без потерь, ссылки и изображения работают.
- Вложение, вставленное на Android, открывается на Windows и в вебе, и наоборот.
- Крипто: тест-векторы, отсутствие plaintext на диске (проверено инструментально), внешний обзор пройден.
- Перф-бюджеты §10 подтверждены на среднебюджетном Android.
- Витринная заметка из дизайна рендерится 1:1 во всех темах и плотностях.
- Ни одной строки цвета/шрифта мимо `tokens.json`.
- Ни одного клинического демо-данного в коде, фикстурах, тестах и скриншотах.
