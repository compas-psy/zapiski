## Короткий ответ

```
1. text-secondary: #726C60
2. gold accent:    #8F6B26
3. gold on-soft:   #886522
```

Все три — принять. Спор «спецификация против DoD» решается в пользу **DoD**: порог 4.5:1 остаётся, значения уступают. Замер был прав, реализация ни при чём.

Ниже — ещё три правки, которые я прошу внести тем же коммитом: они закрывают пары из раздела «вне списка DoD». Без них мы формально зелёные, но ценник на paywall по-прежнему нечитаемый.

## Почему именно так, а не «поднять кегль»

Третий путь из брифа отклоняю. Сниппет 13 px — несущая величина: на нём построена высота строки списка (74 px обычная / 58 компактная) и, как следствие, виртуализация с фиксированной высотой. Переход на 14 px/600 меняет плотность экрана, ритм и заодно делает сниппет визуально равным заголовку строки (15/600) — иерархия схлопывается. Сдвиг цвета на полтона не меняет ничего, кроме цвета.

## Правка 4. Развести «цвет статуса» и «текст статуса»

Корень провала бейджа «подписка» (2.87) — архитектурный: один токен работает и заливкой индикатора, и текстом на soft-подложке. Это разные требования WCAG: **3:1 для нетекстового элемента** (точка синка, галочка, иконка) и **4.5:1 для текста**. Один цвет не может обслуживать оба, если не жертвовать одним из них.

Поэтому у каждого функционального цвета появляется вторая роль — `*-text`:

| Роль | Светлые темы | Контраст на своей soft-подложке |
| --- | --- | ---: |
| `--success` (точка, галочка, иконка) | `#5C8A6E` — без изменений | 3.39 — нетекстовое, порог 3:1 ✓ |
| `--success-text` (текст бейджа «бесплатно») | **`#3F6B51`** | 5.25 ✓ |
| `--warning` (индикатор) | `#B08430` — без изменений | — |
| `--warning-text` (бейдж «подписка», ценник) | **`#886522`** | 4.52 ✓ |
| `--danger` (иконка удаления) | `#A85045` — без изменений | 4.42 — нетекстовое ✓ |
| `--danger-text` (текст ошибки на плашке) | **`#9C463C`** | 5.14 ✓ |

`--warning-text` намеренно равен новому `--accent-on-soft` «Золота»: подложка у них одна и та же (`#F5EBD8`), два разных значения на одном фоне были бы шумом.

## Правка 5. Сдвиг шкалы вторичного текста на одну ступень

`--text-tertiary` при 2.09:1 — вы правы, это уже не «тише всех», это край читаемости. Но просто затемнить его нельзя: между `--text-secondary` `#726C60` (4.99) и ним не останется различимого шага, и три ступени иерархии превратятся в две.

Решение — сдвинуть всю шкалу вниз на одну ступень. Освободившееся значение `#8A8375` (старый secondary) становится третичным: это ровно тот полутон, которого не хватало.

| Токен (светлые темы) | Было | Стало | Контраст на `--bg` |
| --- | --- | --- | ---: |
| `--text` | `#38342E` | без изменений | 11.84 |
| `--text-secondary` | `#8A8375` | **`#726C60`** | 4.99 |
| `--text-tertiary` | `#B6AFA2` | **`#8A8375`** | 3.60 |
| `--text-disabled` | `#C8C1B4` | **`#B6AFA2`** | 2.09 |
| `--text-ghost` (новый) | — | **`#C8C1B4`** | 1.6 |

И жёсткое правило употребления, которого в ТЗ не хватало:

- `--text-secondary` — **любой текст, который человек читает**: сниппеты, пояснения, цитаты, подписи под полями.
- `--text-tertiary` — метаданные, которые пробегают глазами и всегда продублированы контекстом: даты, счётчики, единицы. **Никогда** — единственный носитель смысла.
- `--text-disabled` — только неактивные контролы (WCAG выводит их из-под требования) и рамка невыбранного чекбокса.
- `--text-ghost` — только декоративное: символы markdown вне курсора, «неподтверждённый хвост» расшифровки, разделители. Никогда не текст.

**Плейсхолдеры полей и подсказка пустого редактора переезжают с `--text-disabled` на `--text-tertiary`** — это подсказка, которую нужно прочитать.

Тёмные темы пересчёта не требуют: там все ступени и так с запасом (`--text-secondary` `#9B948A` на `#232120` — 6.1).

## Патч

```css
/* packages/ui/src/styles/tokens.css */

:root[data-theme="paper"] {
  --text:            #38342E;
  --text-secondary:  #726C60;  /* было #8A8375 — 3.60 → 4.99 */
  --text-tertiary:   #8A8375;  /* было #B6AFA2 — 2.09 → 3.60 */
  --text-disabled:   #B6AFA2;  /* было #C8C1B4 */
  --text-ghost:      #C8C1B4;  /* новый: декоративное, не текст */
}

/* акцент «Золото», светлые темы */
[data-accent="gold"] {
  --accent:          #8F6B26;  /* было #B08430 — 3.25 → 4.68 */
  --accent-soft:     #F5EBD8;  /* без изменений */
  --accent-on-soft:  #886522;  /* было #8E6A24 — 4.19 → 4.52 */
}

/* функциональные цвета, светлые темы: индикатор ≠ текст */
:root[data-theme="paper"] {
  --success:         #5C8A6E;  --success-soft: #E7F0E8;  --success-text: #3F6B51;
  --warning:         #B08430;  --warning-soft: #F5EBD8;  --warning-text: #886522;
  --danger:          #A85045;  --danger-soft:  #F6E5E2;  --danger-text:  #9C463C;
  --info:            #4C6B94;  --info-soft:    #E4EAF2;  --info-text:    #3D577A;
}
```

Белый текст на основной кнопке «Золота» после правки даёт **4.88** — отдельный токен для подписи на заливке не нужен, кнопка остаётся белой во всех шести акцентах.

## Что меняется в тесте

Порог 4.5:1 остаётся для всех пяти пар DoD и **дополняется** тремя парами «текст статуса на своей подложке» (`*-text` / `*-soft`) — раньше они не проверялись, а это ценник и текст ошибки.

Отдельным порогом 3:1 (нетекстовые элементы, WCAG 1.4.11) проверяются `--success`, `--warning`, `--danger`, `--accent` как заливки индикаторов и границы полей.

`--text-tertiary` (3.60), `--text-disabled` и `--text-ghost` вносятся в список принятых отклонений с обоснованием: «метаданные, дублированные контекстом» / «неактивные контролы, исключены WCAG 1.4.3» / «декоративные элементы». Тест сторожит их значения от случайного изменения, но не требует 4.5.

Ожидаемый итог прогона: **0 нарушений из 90 пар DoD + 24 новых пары статусов**.
