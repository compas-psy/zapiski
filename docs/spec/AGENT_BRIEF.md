# AGENT BRIEF — как запускать агента на этом ТЗ

Пакет рассчитан на любого агента-разработчика. Ниже — готовые стартовые промпты и правила, одинаковые для Claude Code и ChatGPT.

---

## Стартовый промпт — Claude Code

```
Прочитай design_handoff_zapiski/README.md, DESIGN_TOKENS.md, COMPONENTS.md, SCREENS.md и BEHAVIOR.md целиком (VOICE.md — при переходе к P1),
затем открой ЗАПИСКИ Дизайн.dc.html в браузере как визуальный референс.

Контекст: мы строим КОМПАС.ЗАПИСКИ — Markdown-заметочник (Android, Windows, Web).
HTML в пакете — это дизайн-референс, а не код для копирования.

Начни с Этапа 0 (README §7): спайк Tauri 2 Android + CodeMirror 6 на качество
IME-ввода кириллицы. Прежде чем писать код:
1) составь план работ по шагам и покажи мне;
2) зафиксируй решения по стеку в docs/adr/;
3) заведи токен-слой из DESIGN_TOKENS.md как единственный источник цвета и собери библиотеку из COMPONENTS.md прежде, чем верстать экраны.

Правила: никаких хардкоженных цветов вне токенов; ни одного SMS-зависимого пути;
русский интерфейс на «вы»; строки — только через i18n-каталоги.
Останавливайся и спрашивай, если спецификация чего-то не покрывает.
```

## Стартовый промпт — ChatGPT / Codex

```
Ниже — техническое задание на приложение КОМПАС.ЗАПИСКИ (файлы README.md,
DESIGN_TOKENS.md, COMPONENTS.md, SCREENS.md, BEHAVIOR.md, VOICE.md). Прочитай их полностью, прежде чем отвечать.
При расхождениях приоритет: BEHAVIOR.md > SCREENS.md > DESIGN_TOKENS.md > README.md.

Твоя роль — ведущий инженер. Первый ответ: план реализации Этапа 0 и Этапа 1
(README §7) с разбивкой на задачи, оценкой и списком открытых вопросов ко мне.
Код — только после согласования плана.

Ограничения, которые нельзя нарушать: file-over-app (источник истины — .md на
диске); local-first; zero-knowledge шифрование; никакой SMS-авторизации;
все цвета — из DESIGN_TOKENS.md через CSS-переменные; интерфейс на русском, «вы».
```

## Правила работы агента (общие)

1. **Спецификация важнее догадки.** Если значения нет в `DESIGN_TOKENS.md`, поведения — в `BEHAVIOR.md`, а layout — в `SCREENS.md`, то спросить, а не изобретать. Приоритет при расхождении: `BEHAVIOR.md` > `SCREENS.md` > `DESIGN_TOKENS.md` > `README.md`.
2. **Порядок этапов не менять.** Ядро → редактор → экраны → синк → облако. Экраны без ядра дадут красивый нерабочий макет.
3. **Каждый этап заканчивается проверяемым артефактом:** CLI-демо ядра, витринная заметка в редакторе, альфа-сборка, зелёный сьют «злого синка».
4. **Тесты — часть определения готовности,** а не отдельная задача в конце. Ядро >80% покрытия, e2e-ввод на реальных Android-устройствах.
5. **Красные линии продукта** (README §1) обсуждению не подлежат: никаких БД, канбанов, плагинов, геймификации.
6. **Приватность по умолчанию:** ни одна аналитика не отправляет содержимое заметок; аналитика включается пользователем, а не выключается.
7. **Пиши ADR** (`docs/adr/NNN-название.md`) на каждое архитектурное решение, отличающееся от рекомендованного в §2.2.

## Открытые вопросы, требующие ответа заказчика

- Домен и почтовый провайдер для magic-link (нужен транзакционный email, не SMS).
- Регистрация приложения в Яндекс OAuth (client_id) — кто делает.
- Юрлицо и подключение Т-Кассы (Т-Банк). Магазин для Android — отдельное решение: Google с декабря 2024 не платит российским разработчикам.
- Хостинг KompasCloud в РФ (провайдер, S3-совместимое хранилище).
- Нужен ли Telegram Login как третий способ входа на MVP или это P1.
- Юридическая проверка лицензии конкретных весов GigaAM под коммерческое использование (`VOICE.md` §9) — до начала этапа V1.
