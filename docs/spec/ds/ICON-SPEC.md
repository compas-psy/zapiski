# СИМПАС — как делать иконку приложения

> Файл из пакета дизайн-системы СИМПАС (11.09.2026), положен в репозиторий как есть —
> правится только у источника. В ЗАПИСКАХ слои собирает `scripts/gen-icons.mjs`,
> а крупность в готовых файлах меряет `scripts/check-icon-scale.mjs`.

**Кому.** Любому агенту или разработчику, который собирает иконку приложения любого сервиса СИМПАСа. Документ самодостаточный: дизайн-система для него не нужна, ничего домысливать не требуется. Делайте ровно по числам.

**Проблема, которую он закрывает.** Знак дерева один на все девять сервисов, поэтому единственное, что может разъехаться, — **крупность дерева внутри плитки**. И она разъезжается: в одном приложении дерево распирает плитку до краёв, в другом сиротливо болтается в середине. Рядом на домашнем экране это выглядит как иконки разных компаний.

---

## 1. Единственное правило крупности

> **Высота дерева = 60 % высоты видимой плитки. Чистое поле — по 20 % сверху и снизу.**

Всё остальное в этом документе — перевод этого правила на конкретные платформы. Запомнить надо одно число: **0,60**.

Ориентиры, чтобы поймать ошибку на глаз:

| Что видно | Доля | Вердикт |
| --- | --- | --- |
| дерево почти касается краёв, поля тоньше ветки | 0,80–0,90 | **слишком крупно** |
| дерево уверенно занимает середину, поля ≈ по полторы толщины ветки | **0,60** | **верно** |
| вокруг дерева пустая рамка шириной в само дерево | 0,45 и меньше | **слишком мелко** |

**Видимая плитка** — то, что остаётся после маски платформы, а не размер вашего холста. На Android это центральные 72 dp из 108 dp, а не все 108. Перепутать эти две величины — ровно та ошибка, из-за которой иконка на устройстве выходит на треть крупнее задуманного.

---

## 2. Геометрия знака

Дерево берётся готовым из `packages/ui/src/assets/services/*.svg`. Контур не перерисовывается, не упрощается и не дополняется — никогда, ни для одного сервиса, ни ради «оптической компенсации».

Внутри исходного `viewBox="0 0 500 500"` знак занимает:

| Параметр | Значение |
| --- | --- |
| bounding box | `x 105 · y 95 · w 290 · h 310` |
| центр bbox | `250 250` — точно центр viewBox |
| пропорция (ш/в) | 0,935 |

Центр знака совпадает с центром viewBox, поэтому **оптическая подгонка не нужна**: геометрического центрирования достаточно.

Отсюда пересчёт под любую плитку со стороной `S`:

```
высота дерева = 0.60 × S
ширина дерева = 0.561 × S
scale к исходному пути = (0.60 × S) / 310
```

## 3. Числа по платформам

### Плоская плитка — iOS, веб, стор, favicon, маркетинг

Холст квадратный, видимая плитка = весь холст.

| Сторона холста | Высота дерева | Ширина дерева | `scale` к пути 500×500 |
| --- | --- | --- | --- |
| 1024 (App Store) | 614 | 574 | 1,9820 |
| 512 | 307 | 287 | 0,9911 |
| **500** (наш исходник) | **300** | **281** | **0,967742** |
| 180 (iOS @3x) | 108 | 101 | 0,3484 |
| 108 | 65 | 61 | 0,2090 |

Скругление плитки — 0,28 стороны (squircle). **Для iOS и для сторов углы не скругляются вообще** — платформа накладывает маску сама; отдаётся квадрат с заливкой под срез.

Готовый SVG — просто подставьте цвета сервиса и путь дерева:

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 500 500">
  <rect width="500" height="500" rx="140" fill="ЦВЕТ-ФОНА"/>
  <g transform="translate(250 250) scale(0.967742) translate(-250 -250)">
    <path fill-rule="evenodd" clip-rule="evenodd" fill="ЦВЕТ-ДЕРЕВА" d="…"/>
  </g>
</svg>
```

### Android adaptive icon

Холст **108 × 108 dp**. Маска лаунчера вырезает **центральные 72 dp** и растягивает их на всю плитку. Внешние 18 dp с каждой стороны — запас на параллакс, их **не видно никогда**. Считать крупность надо от 72, не от 108.

| Параметр | Значение |
| --- | --- |
| холст | 108 × 108 dp |
| видимая зона (маска) | центральные 72 dp |
| гарантированно безопасный круг | 66 dp |
| **высота дерева** | **43,2 dp** (0,60 × 72) |
| ширина дерева | 40,4 dp |
| центр | 54 · 54 |
| `scale` к пути 500×500 | **0,139355** |

```svg
<!-- ic_launcher_foreground -->
<svg xmlns="http://www.w3.org/2000/svg" width="108" height="108" viewBox="0 0 108 108">
  <g transform="translate(54 54) scale(0.139355) translate(-250 -250)">
    <path fill-rule="evenodd" clip-rule="evenodd" fill="ЦВЕТ-ДЕРЕВА" d="…"/>
  </g>
</svg>
```

Три слоя, по одному файлу на каждый:

| Слой | Содержимое |
| --- | --- |
| `ic_launcher_background` | сплошная плашка цвета сервиса на всех 108 dp. Ни градиента, ни тени, ни блика |
| `ic_launcher_foreground` | дерево цветом сервиса, фон прозрачный |
| `ic_launcher_monochrome` | то же дерево сплошным чёрным, без полутонов и внутренней прозрачности — система работает с ним как с маской |

```xml
<!-- res/mipmap-anydpi-v26/ic_launcher.xml -->
<adaptive-icon xmlns:android="http://schemas.android.com/apk/res/android">
    <background android:drawable="@drawable/ic_launcher_background" />
    <foreground android:drawable="@drawable/ic_launcher_foreground" />
    <monochrome android:drawable="@drawable/ic_launcher_monochrome" />
</adaptive-icon>
```

**Углы у Android-слоёв не скругляются.** Маску даёт лаунчер; своё скругление поверх системного даёт двойной контур.

**Осторожно с предпросмотром.** Превью, которое показывает весь холст 108 dp, врёт: дерево в нём выглядит на треть мельче, чем окажется на устройстве. Проверять только на кропе центральных 72 dp — файлы `*-preview.svg` уже собраны так, они и есть эталон приёмки.

### Внутри интерфейса — переключатель сервисов, списки, шапки

Компонент `ServiceMark` из дизайн-системы (`shape="squircle" | "rounded" | "circle"`) уже держит 0,60. Если рисуете руками: та же формула, скругление 0,28 стороны для squircle и 0,18 для мягкого квадрата.

Иконка обязана читаться **на 28 px**. Ниже ветви кроны слипаются в пятно — на таких размерах берите `bare` (одно дерево без плашки) или монохромный силуэт.

## 4. Цветовые пары

Единственное, чем сервисы различаются. Фон и дерево берутся **строго парой** из этой таблицы — свои оттенки не подбираются.

| Сервис | Фон | Дерево |
| --- | --- | --- |
| ПРАКТИКА | `#1D4735` | `#F7F8F4` |
| МОМЕНТЫ | `#4A4E78` | `#EDEBF2` |
| ЗАПИСКИ | `#C8604A` | `#FBF3E3` |
| ШАГИ | `#3B8F5A` | `#F7F8F4` |
| СТУПЕНИ | `#CC9E50` | `#143D2F` |
| ГРАНИ | `#5C2F42` | `#F5EAEF` |
| КРУГИ | `#6A5F63` | `#F7F3F1` |
| СВОИ | `#A47864` | `#FAF5F0` |
| ДНЕВНИК | `#E7F0EA` | `#1D4735` |

Внутренняя обводка плитки ставится только двум светлым — СТУПЕНИ и ДНЕВНИК — и только чтобы плитка не растворялась на светлых обоях.

---

## 5. Чего не делать

- **Не менять крупность «на глаз».** 0,60 — не рекомендация, а единственное, что держит семейство вместе.
- **Не считать крупность от холста 108 dp на Android.** Только от видимой зоны 72 dp.
- **Не менять контур дерева** — ни обрезок, ни перерисовок, ни добавленных элементов, ни поворотов, ни зеркала.
- **Не заливать плитку градиентом**, не добавлять тень, блик, внутреннее свечение, обводку (кроме двух светлых сервисов) и текстуру.
- **Не писать название внутри плитки.** Имя рисует лаунчер и система.
- **Не скруглять углы** там, где маску даёт платформа (iOS, сторы, Android adaptive).
- **Не подбирать цвета** вне таблицы выше и не смешивать фон одного сервиса с деревом другого.
- **Не ставить дерево не по центру** и не подгонять положение оптически — центр bbox уже совпадает с центром холста.

## 6. Приёмка — проверка за десять секунд

Откройте иконку в том виде, в каком её увидит пользователь (для Android — кроп центральных 72 dp), и измерьте линейкой или в инспекторе:

```
высота дерева ÷ высота видимой плитки = 0.60   (допуск ±0.02)
```

Если получилось больше 0,65 — крупно, меньше 0,55 — мелко. Пересчитайте `scale` по формуле из раздела 2 и пересоберите.

Дальше по списку:

- Дерево по центру, поля сверху и снизу равны (по 20 %).
- Фон — сплошная плашка цвета сервиса, без эффектов.
- Пара «фон + дерево» совпадает с таблицей раздела 4 посимвольно.
- Контур дерева не отличается от `packages/ui/src/assets/services/*.svg`.
- Android: три слоя на месте, `monochrome` — сплошной чёрный, углы не скруглены, дерево внутри 66 dp.
- Надписей внутри плитки нет.
- Иконка читается на 28 px.
- Три иконки разных сервисов, поставленные рядом, выглядят одним семейством: дерево одинаковой крупности, различается только цвет.

Последний пункт — главный. Если рядом видно разницу в крупности, иконка не принята, каким бы аккуратным ни был остальной файл.
