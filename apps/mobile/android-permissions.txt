# Разрешения Android — единственный источник истины.
#
# Отсюда их берёт `scripts/apply-android-overlay.mjs` при патче манифеста, и с
# этим же файлом CI сверяет ГОТОВЫЙ APK (`aapt dump permissions`). Шаблон
# манифеста и итоговый пакет — разные вещи: Tauri генерирует манифест сам, и
# разрешение может приехать из зависимости, которую никто не звал.
#
# Формат: имя, затем `maxSdkVersion=N` при необходимости, затем `#` и
# объяснение — зачем оно и что сломается без него. Строка без объяснения не
# проходит проверку: разрешение без причины — это разрешение, которое никто не
# пересмотрит.
#
# ── Чего здесь нет и не будет ────────────────────────────────────────────────
#
# android.permission.REQUEST_INSTALL_PACKAGES — убрано 23.08.2026.
# Им приложение объявляет себя установщиком ДРУГИХ приложений; это признак, по
# которому Play Protect ловит дропперы, и из-за него блокировалась КАЖДАЯ
# установка ЗАПИСОК со вторым окном «всё равно установить». Соседние продукты
# на том же телефоне ставятся молча: МОМЕНТЫ просят только INTERNET, ПРАКТИКА —
# RECORD_AUDIO. Нужно оно было самоустановке обновлений; теперь приложение
# открывает ссылку на APK во внешнем браузере, и «из неизвестных источников»
# система спрашивает у браузера, а не у нас.

android.permission.INTERNET
  # Облако целиком: вход, синхронизация, фид обновлений, отправка аналитики.
  # Без него приложение остаётся локальным блокнотом — режим поддержанный, но
  # не единственный.

android.permission.VIBRATE
  # Хэптика (BEHAVIOR §0) — `Vibrator.vibrate` в `NativeBridge.haptic`, там
  # где у жеста нет иного отклика. Без строки система бросает
  # SecurityException на каждый отклик.

android.permission.USE_BIOMETRIC
  # `BiometricPrompt.authenticate()` и `BiometricManager.canAuthenticate()`
  # помечены `@RequiresPermission(USE_BIOMETRIC)`. Строки не было — и это
  # стоило дорого: `canAuthenticate` глотал исключение и отвечал «биометрии
  # нет», палец не предлагался ни разу, а `authenticate` бросал то же
  # исключение на ГЛАВНОМ потоке — приложение падало при включении тумблера.
  # Уровень защиты `normal`: у человека ничего не спрашивают.

android.permission.USE_FINGERPRINT maxSdkVersion=28
  # Android 9: `BiometricManager` появился только в 10, поэтому честный ответ
  # «есть ли отпечаток» там даёт `FingerprintManager`, а он требует своё,
  # устаревшее разрешение. `maxSdkVersion` держит его ровно там, где оно
  # нужно, и не тащит в листинг на новых версиях.

ru.cmpas.zapiski.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION
  # Не наше и не системное: его объявляет САМА библиотека AndroidX Core, когда
  # приложение регистрирует неэкспортируемый широковещательный приёмник —
  # уровень защиты signature, то есть выдать его может только пакет с нашей же
  # подписью. У человека оно ничего не спрашивает и в списке разрешений на
  # телефоне не показывается.
  #
  # В списке оно потому, что ЕСТЬ В ПАКЕТЕ. Нашла его эта самая проверка на
  # первом же прогоне: в шаблоне манифеста его не видно — Tauri и AndroidX
  # дописывают манифест при сборке. Молчать о нём значило бы либо ослабить
  # сверку, либо ронять каждую сборку.
