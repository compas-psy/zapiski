# Отладочный ключ подписи Android

## Главное, одной строкой

**Debug-APK — артефакт разработки. Производственной сборкой он не является
никогда и по пользовательским адресам скачивания и обновления не публикуется:
ни в `/updates/latest/zapiski.apk`, ни в `latest.json`, ни в GitHub Release.**

Для производственной подписи достаточно полного комплекта четырёх секретов —
`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`,
`ANDROID_KEY_PASSWORD`. Никакого дополнительного секрета подписи не требуется.
Неполный комплект — не повод собрать debug: сборка падает, потому что половина
настройки это ошибка, а не выбор.

## Зачем он лежит в репозитории

Без секретов подписи (`ANDROID_KEYSTORE_BASE64` и соседних) сборка выпускает
**debug-APK**, а его подписывает отладочный ключ Android-плагина. Этот ключ
плагин генерирует случайным **на той машине, где собирает**. Каждый прогон
GitHub Actions — новая чистая виртуалка, то есть новый ключ и новая подпись.

Последствие ровно одно, зато злое: первая сборка ставится, а каждая следующая
отказывается. Android не даёт установить пакет с тем же `applicationId`, но
чужой подписью, и показывает «Приложение не установлено» — без объяснения
причины. Заказчик потратил на это вечер: Play Защита выключена, «установка из
неизвестных источников» разрешена, а APK всё равно не встаёт.

`debug.keystore.base64` делает подпись debug-сборок **постоянной**: любая
следующая ставится поверх предыдущей, как и должно быть.

## Почему это не утечка

Ключ отладочный и ничего не защищает:

* пароль и алиас — общеизвестные значения Android (`android`,
  `androiddebugkey`), точно такие же лежат в `~/.android/debug.keystore` у
  каждого, кто хоть раз собирал Android-проект;
* в Google Play подписанное им приложение не принимается;
* обновлением поверх релизной сборки такой APK не встанет — у релиза другой
  ключ, и это правильно;
* владение им не даёт доступа ни к данным пользователей, ни к серверу.

**Релизный ключ здесь не лежит и лежать не может.** Он живёт только в секретах
репозитория; как только они появятся, сборка перестанет пользоваться этим
файлом сама — см. шаг «Подготовить keystore» в `build-android.yml`.

## Чего постоянный отладочный ключ НЕ решает

Он решает ровно одно: debug-сборка ставится поверх предыдущей debug-сборки.

Он **не** делает пакет производственным и **не** снимает вопросов Play Защиты.
Для неё `CN=Android Debug` — первый признак того, что приложение собрано не для
людей, и проверка подписи при установке к отладочному ключу относится именно
так. Поэтому дорога «нет секретов → отладочный ключ → публичная ссылка» из
сборки убрана целиком: правило и его проверки описаны в шапке
`.github/workflows/build-android.yml`, а логика — в
`apps/mobile/scripts/android-release-gate.mjs` (испытывается
`apps/mobile/test/android-release-gate.test.ts`).

## Как заменить

```sh
keytool -genkeypair -v -keystore debug.keystore \
  -storepass android -alias androiddebugkey -keypass android \
  -keyalg RSA -keysize 2048 -validity 10950 \
  -dname "CN=ZAPISKI Debug, OU=Development, O=SIMPAS, L=Moscow, C=RU"
base64 -w 100 debug.keystore > debug.keystore.base64
```

После замены все, у кого стоит debug-сборка, должны будут удалить приложение и
поставить заново — подпись сменится. Поэтому менять его без нужды не стоит.
